# Conditional per-key realization and completed-operation trace proof


## Explicit premises and what the transfer proves

This exposition does not prove the Java Memory Model or the entire map implementation. It proves a conditional transfer for an operation interface, using the following premises. The later source/control-point discussion identifies why the pinned wrappers and API are intended to meet them; source inspection and finite traces are separate from the mathematical transfer.

| Premise | Required property | Evidence or assumption status |
|---|---|---|
| A1: persistent per-key map | Distinct permanently present keys, non-null immutable values, identity validation, stable normally terminating key methods; one foreground controller. Existing keys may collide in bins. | Declared wrapper/input restriction. Public replace may call equals, so an identity-equality value class is required. |
| A2: operation boundaries | Each selected get returns a value from that key at a point during the call; conditional replacement atomically checks and updates; compute invokes the remapping callback once with same-key publications excluded through its store. | Per-key API/source property assumed by the transfer; cited source paths are not a full JMM proof. |
| A3: indivisible whole work | Every protected or unprotected kernel uses only its captured immutable own operands and exact completed-parent tuple; every invocation pays its specified fixed work. No kernel has live reads, recursive map updates, partial reuse or other-key work. The controller cannot directly acquire a writer-excluding guard or retain any protection between wrapper calls. | Declared kernel/callback language. Instrumentation is projected separately. |
| A4: saved observations and records | Output comes from the saved wrapper result; completion milestones are immutable. Available records and opaque-reference equality are preserved by an injective reference map. After a call gate, selection uses only the already-computed pre-gate store; any new preparation has a later comparison gate. | Declared observation/interface contract. Cheap exposes only success/failure; cached exports the Boolean for visible-comparison results. Erased-observation results require their stricter full-history erasure. |
| A5: fresh target writes | At a boundary with no foreground guard held, a terminating target writer can publish a legal reference fresh to the finite preceding history/store, including old raw snapshots. Writers preserve job shape and completed milestones. | Legal environment capability, not inferred from finiteness alone or from a finite sample. It is exactly the lower-bound adversary's needed capability. |
| A6: progress and costs | Selected primitives terminate under admitted schedules; unbounded foreground polling remains inadmissible. Cost counts completed kernel work and wrapper validations/completions from the charged common start. | Explicit progress/resource assumptions. No finite wall-clock bound or scheduler-fairness theorem follows. |

**Conditional transfer.** Under A1--A6, completed wrapper traces admit an abstract gate-trace projection preserving the declared foreground results, reference-equality relations, milestones and resource totals Q,W,L, without increasing the count of committed external writes. The emitted finite policies therefore inherit their abstract resource upper bounds. For the all-program lower bounds, the fresh target writes used by the abstract proof can be scheduled before the selected API entry, and the same distinct-charge argument applies to every admitted whole-wrapper program. These two directions, plus their stated progress/admissibility hypotheses, transfer the optimality statements. It is not necessary to assert that every low-level Java execution is a stepwise simulation of the abstract machine.

Resource labels in the projection are **ghost quantities compared by the proof or checker**, not additional observations supplied to the controller. In particular, hidden protected-work counters cannot be used to recover an erased comparison outcome. The controller's permitted observations are the listed wrapper returns, saved state and allowed inspections only.

**The strict erased case, defined explicitly.** For each job fix one immutable object z_i. Every complete execution of that job's kernel still performs its prescribed work but returns this same object, for both preparation and protected recomputation. A cached call's entire visible transition exposes only that output and completion: it retains no compared input, Boolean, comparison-dependent record selection or callback-local side effect. Work counters, clocks, allocation identifiers and kernel internals are hidden. Free outside inspections, old snapshots and retained preparations remain allowed. Both cached branches publish/save z_i; comparing a retained prepared output with M(i) therefore returns equal in both branches. Milestones remain immutable and records need not be deleted. Returning the same payload in distinct new objects would be insufficient, as would saving the callback's current input elsewhere.

This is the manuscript's constant-output/full-history-erasure contract. It is an additional restriction for erased-observation results, not a property of every allocating or arbitrary-output wrapper. A wrapper returning a newly allocated result on mismatch can reveal that outcome through reference comparison even if the Boolean is hidden; such a wrapper is outside this strict erased case. The phrase 'a newly allocated output' in the source-boundary discussion describes how an allocation, when used, is represented; it does not require every kernel to allocate a new returned object. Ghost preservation of Q-prime is a cost-accounting statement and does not itself establish observational erasure.


The transfer supports the body-work claims, with positive guard/comparison fees fixed to zero for this realization. It does not identify mathematical guard prices with native instruction counts or elapsed time. A real implementation that violates an A-premise has no guarantee from this theorem even if one finite test happened to agree.

This expands the preserved [earlier Java proof](evidence/RESUMED_20260910_1617/java_refinement_01/OPERATION_TRACE_REFINEMENT_02.md). The theorem concerns the declared whole-kernel wrapper interface. No new native execution or experimental outcome is introduced.

## Source boundary and admitted executions

Use the pinned [OpenJDK17 ConcurrentHashMap source](https://github.com/openjdk/jdk17u/blob/982d53c227943a511e8d61694feced764b71a6c1/src/java.base/share/classes/java/util/concurrent/ConcurrentHashMap.java) at commit `982d53c227943a511e8d61694feced764b71a6c1` and the [Java17 API specification](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/ConcurrentHashMap.html). Source line locators below refer to that commit. There is one foreground controller. Each job has a distinct permanent existing key; keys can share internal bins. Key hash/equality/comparison methods are stable, side-effect-free and terminate normally. Values are nonnull; equality for validation is reference identity. Every published Value is deeply immutable after construction, including arrays; its job tag and shape are preserved by kernels and external writers. An external own-key write normally completes, installs a reference not previously used for that job, and neither removes a key nor changes completed milestones. At every finite execution prefix the admitted environment can perform another such write. Resource exhaustion, arbitrary exceptions, recursive map updates from a remapping function, key deletion, and unfair nontermination of a selected API operation are outside this contract.

The kernel reads only its immutable own snapshot and immutable completed-parent outputs. Its payload computation is pure and performs its specified fixed work. A newly allocated output is treated as a fresh opaque reference carrying that payload: reference renaming preserves aliasing, validation and specified observations. This allows allocation without claiming that repeated allocations have equal Java references. The controller does not observe numeric allocation counters, event-log order, wall time, scheduling probes or mutable live-parent reads inside the kernel. A kernel that uses any such value to choose its result or controller action requires another model.

For the normal baseline, excluding live_parent and other deliberate mutants, the retained controller observations are reference equality, payload, saved wrapper return, done-parent outputs and selector state. Q/W/L are ghost resource labels preserved by the proof/checker, not implicit controller observations. The excluded observations are numeric IDs, event order, diagnostic failure witnesses, clocks and scheduling probes. The particular instrumented [BudgetBlindCallbacks.java](evidence/RESUMED_20260909_0056/charged_budget_blind_native_01/BudgetBlindCallbacks.java) has diagnostic ids.incrementAndGet, event writes, Thread.yield and resource counters. Its selector reads dependencies, the mode family and call allowance; the arithmetic payload kernel reads snapshot data and done-parent seeds, not diagnostic ids. Erasing these diagnostic fields/actions and consistently renaming remaining object references specifies the wrapper experiment's payload/action projection. This is not an observational equivalence for callers inspecting all fields, writer histories, log order or numeric IDs. The finite event checker validates those instrumentation traces separately. The abstract theorem is stated for the pure wrapper contract, not inferred by declaring every instrumented instruction pure.

## Concrete state and abstraction relation

Let H be the concrete heap, including map nodes, immutable Value objects, the foreground's done array, snapshot/record store and locals. Add proof-only variables: a finite ordered queue Delta of committed external writes deferred during normalization, whose elements are committed write labels (key, new reference), not writer callbacks to be rerun. Let eta be an injective map from every reference needed by the concrete/abstract live states, available records, pending-write queue and ghost computation history to opaque abstract identities, extended to new references without identifying distinct objects. A reference occurring only in Delta remains in its domain even if a later concrete write has overwritten it. It carries the immutable payload needed by the fixed kernel and preserves reference equality.

The abstract state is (x,M,R,ell). M(i)=eta(done[i]) once the job completes and is thereafter immutable. R contains only snapshot/record handles actually available for selection by the foreground. A separate ghost history may record past computations, but never makes a discarded handle selectable. The simple native loop keeps only its current before/prepared handles; it does not implement the entire retained/copying strategy class. A general wrapper implements that class only when it really stores the corresponding handles. Available computed records have the form (i,eta(s),P_i,eta(z)); P_i is the tuple of M(p) for completed immediate predecessors. Records may be copied/reselected but cannot be fabricated or retagged. ell contains the controller state and selected handles. A completed source result is put in M from the API's saved return/prepared value, never by rereading the live map.

At normalized wrapper boundaries the live-reference relation is

    decode_eta(H.map)=apply(Delta,x),
    b_concrete=b_abstract+|Delta|.

Here apply replays each queued committed assignment label in its concrete order. b_concrete is a ghost count of committed external-writer assignments only, not foreground stores and not the diagnostic Run.writes counter: that counter increments inside the writer callback before CHM performs its store, and can temporarily lead the commit count. At synchronized completed-writer boundaries their counts agree. A successful foreground publication or the validation-only callback re-storing the same reference does not increment this external count. The definition is not a filter counting only value-changing stores: an external assignment counts whenever the environment contract admits it, even if it has no useful validation effect. When Delta is empty this is ordinary equality of live abstract and concrete values. The queue is needed because a writer may run after a remapping result is fixed but before the public API returns. For example, a cached call publishes z, a later writer publishes y, and compute still returns z. Mapping the return-time live map directly to the pre-suffix abstract x would be wrong.

decode_eta follows MOVED/forwarding nodes to the appropriate table and reads stored Value references, ignoring node allocation identities. Its definition is used at stable operation boundaries; this document does not claim a one-line heap function adequately describes every intermediate resize state. The source's forwarding/monitor invariants connect these boundaries.

## Control points and source evidence

P0 fixes job, mode and the prior record store. P1 covers hashing, table search, forwarding/helpTransfer and retries before a usable bin is acquired. P2 acquires the appropriate bin monitor and validates its head. P3 compares the current value and invokes the completing kernel if required. P4 fixes the result and performs the map publication while still protected. P5 has released the monitor but has not yet returned. P6 delivers the saved result and updates the foreground milestone/flag.

In the pinned existing-key compute path, P2 is source lines1931–1932, list key lookup is1937–1939 and remapping/store is1940–1942, tree remapping/store is1975–1978, the exit from the synchronized path is1993 onward, and the saved val is returned at2003. The captured-identity comparison itself is in the supplied native callback (native101/104), not the CHM key-equality lookup. Pre-monitor retries do not invoke the callback and do not add wrapper calls. Under the API's exactly-once remapping contract and normal completion, P3 is invoked once. A writer on the same key cannot change that value between comparison and publication. Parent milestones are immutable throughout. Colliding distinct keys can add waiting but cannot change these functional facts.

replaceNode saves oldVal on a successful match before publishing, in the list and tree paths at1131–1136 and1155–1160, and returns it at1174 after releasing protection. With nonnull values, public replace's oldVal!=null is exactly the success boolean. The public API may use equals as well as identity, hence the identity-equality Value assumption is essential.

For capture and explicit inspection we additionally use the per-key retrieval/forwarding property: a successful get on a permanently present key returns the reference of a live value at a point during its execution. The source get path934–955 returns the matched node value directly or follows find on a special/forwarding node. We assume the Java API/source per-key retrieval guarantee; node-copy lines alone are not presented as a complete JMM proof. ## Wrapper transition and observation table

Write r=(i,s,P_i,z) for a selected preparation and v for the value observed at P3. Every successful completion additionally sets M(i) to its saved output. The table gives increments at completed wrapper boundaries in units of one specified kernel iteration work w_i.

| Wrapper operation | Returned controller observation | Abstract update | Delta(Q,W,L) |
|---|---|---|---|
| Prepare from a captured snapshot | new record handle r | add r to R; no completion | (0,w_i,0) |
| Cheap match | success flag | x_i:=z; M(i):=z | (1,0,0) |
| Cheap mismatch | failure flag only | clear selection; retain R,M and x | (1,0,0) |
| Fresh completion | completed output z' from current v and P_i | x_i:=z'; M(i):=z' | (1,w_i,w_i) |
| Cached match | completed output z, match flag when the visible-comparison contract is selected | x_i:=z; M(i):=z | (1,0,0) |
| Cached mismatch | completed output z', mismatch flag when the visible-comparison contract is selected | x_i:=z'; M(i):=z' | (1,w_i,w_i) |

The conditional-replace wrapper returns its boolean. A validation-only compute wrapper discards the raw returned value and exposes only its match flag. On mismatch that raw value is v, whereas replace returns false; the unwrapped APIs therefore are not observation equivalent. An interface exposing v must add it to the abstract result/history and prove its own correspondence. The validation-only wrapper code discards that additional value. In this particular fixture its valid input relation g=0,r=v always selects the replace branch at native103, so the validation-only branch104 is not executed by these cases. Its correspondence is a source/API argument, not empirical branch coverage from this fixture. Returning v from a mismatch callback may store the same reference again; its abstract live state remains unchanged and it is not a fresh external write.

The per-operation claims follow directly from the branch and protected-store paths above. Matching records contain the exact own snapshot identity and completed-parent tuple. Nonmatching cached/fresh calls compute from v while same-key writes are excluded. All output payload computations use those immutable operands. A source allocation extends eta with a fresh reference and cannot change an existing record's identity.

## Grouping internal work and structural steps

For BudgetBlindCallbacks the array-length invariant is |src.a|+number_of_parents(i)=8w_i. Initialization establishes it; the writer allocates an array of the same length and preserves slot; every kernel does the same. Each parent iteration and array iteration increments work once, so a whole kernel adds8w_i. A protected kernel additionally increments protectedCalls[i] once. Thus at completed source wrapper boundaries:

    Q=sum_i(callbacks[i]+conditionals[i]),
    W=work/8,
    L=sum_i w_i*protectedCalls[i].

The general wrapper uses w_i directly; the factor8 belongs only to this fixture's implementation scale. We group a completed kernel segment and its full work into one labelled abstract operation and compare costs at the corresponding completed-operation boundaries. No completed result reference or full-cost abstract Prepare is assigned to an earlier unfinished source prefix. An instruction-by-instruction forward simulation would require pending computation descriptors and reserved-token/cost invariants and is not claimed here. Internal work++ steps are therefore not being asserted to be zero-cost stutters. Monitor waits, internal traversal, guard instructions, allocation and elapsed time are outside Q,W,L; no total-time identity follows.

Pure structure changes preserve stored Value references: list transfer2505–2509, tree transfer2523–2524, treeification2675–2677 and untreeification2697 copy those references into replacement nodes. Such structure-only actions preserve x,M,R and counted kernel work. A concurrent value-changing writer during transfer remains a write transition; it is not hidden as structural stuttering.

## Normalization to gates

Fix a completed source execution and the specified foreground observations. Label each completed unprotected preparatory kernel segment by its captured immutable operands, its actual returned output reference and its full work. A protected kernel remains inside the abstract fresh/cached operation; it is not turned into an unprotected Prepare. Contract that segment into one abstract Prepare, retaining the capture event before it. The state immediately after abstract Prepare corresponds to a source boundary after the actual kernel has returned; the output reference therefore exists and eta can include it. Writes committed between capture and that return go into Delta, preserving their order and count, and are flushed before the next selected foreground operation's abstract effect. This is a completed-trace transformation, not a statewise assertion that the output existed at capture. Any intervening foreground inspection is itself that next operation, so it observes the same updated live value. Local record operations receive the same handles and alias relations. For a standalone inspection, place its abstract read at the chosen source read point: earlier commits are flushed before that read, and commits between the read and return are put into Delta for the next gate, preserving the saved return value. During a protected P2--P4 interval, other-key commits through P4 may be placed at this operation's gate. Flush the pre-existing Delta first, then fold these commits in concrete order; commits after P4 remain in Delta. Such reordering does not change this operation's captured own input or saved completed parents. Same-key updates are excluded from that protected interval by A2.

Similarly, after P4 the return value and success flag are fixed in locals. Writes from P5 through P6 can be deferred into Delta; the milestone uses the saved result, so its value is preserved. The concrete map may already contain their results, which is exactly why decode_eta(H.map)=apply(Delta,x), rather than decode_eta(H.map)=x, is maintained. The next gate flushes Delta before the next operation effect. Same-key writer order is preserved. Kernels do not read other mutable entries, so these writes cannot change a contracted pure body. This argument preserves the declared foreground observations and resource totals, not arbitrary writer observations or diagnostic event interleavings.

If execution ends with a nonempty Delta, an observational extension by a zero-foreground-cost terminal write suffix replays it and preserves the final live map. For a completion-cost objective, one may instead stop at the completed foreground prefix, but then must not claim final live-map identity. This proof includes the suffix explicitly.

The fixture's n<=5 fixed-key run does not exercise treeification or resize. Those structural paths are covered by the stated source/API reasoning, not added to its native coverage count. Diagnostic erasure and fresh-reference renaming describe a possible trace projection under the allowed scheduler, not equal execution under an identical fixed machine schedule.

Because normalization never adds a write, a concrete source execution with at most B writes maps to an abstract execution within B and with identical completed-wrapper Q,W,L. For the explicit upper-bound strategies, control executes only a bounded number of finite preparation/call segments and completes because each selected source operation terminates. The matching abstract trace transfers their resource bounds. This does not infer termination of arbitrary low-level code from completed traces alone. It is not a claim that all low-level API calls or all arbitrary Java programs belong to this interface.

## Concrete realizability of the lower-bound adversaries

After the foreground has fixed a target job/mode and its finite pre-gate store, suspend it before entering that API. Run a successful writer compute on the target key, installing a legal fresh reference of the required shape, then resume the foreground. No foreground monitor is held at this point, even if bins collide. The new reference differs from every target snapshot captured in the preceding finite store. Hence cheap comparison fails and cached mismatch recomputes inside; a fresh call already protects its full kernel. Lower-bound realizability does not require inserting a write inside an acquired monitor or identifying its last physical acquisition.

Repeat this construction using the target adversary's finite unconditional bound. For Theorem1, before the next target write, actual writes v<=f+p, where f is noncompleting target calls and p is completed targets. While f<=r and p<k, v+1<=f+p+1<=r+k<=B. The adversary stops after f=r+1 or p=k. A source policy that avoids completion through infinitely many free actions against this same bounded adversary is inadmissible; no unjustified arbitrary truncation argument is needed. For Theorem2 the additional write belongs to a distinct finite environment witnessing universal-cap admissibility, not to the original lower-bound execution's evaluation budget.

The lower transfer imports the global distinct-charge lemma, finite concrete-history extraction, and unconditional path-witness cap from [full-program proof](FULL_PROGRAM_PROOF.md); it proves that their needed operations/writes are realizable, not an independent second proof of those abstract lemmas. For a general admitted whole-wrapper program, fix a concrete fresh writer result at each restricted comparison history. The [full-program proof](FULL_PROGRAM_PROOF.md) extraction and global distinct-charge proof then apply to these concrete histories, including preparation paid before the current call. For an emitted policy path with d bad outcomes, use the corresponding concrete prefix writes and stop off that witness, imposing an unconditional cap d on every play. A4 supplies pre-gate computed records, A5 invalidates all retained target records, and no retained foreground guard prevents the writer. Thus the needed all-program lower witnesses are realizable; no claim that every abstract environment has a Java implementation is needed. For the concrete-to-abstract completed-trace projection above, operation-kind and cached-mismatch ghost labels are preserved too, so Q-prime=Q+number_of_cached_mismatches is preserved even under a contract hiding that flag from the controller. A controller may still count its own observed calls.

This proves the source operation realization needed for the stated frontiers, assuming the fixed API/source synchronization properties and normal selected-operation progress. Full JDK/JMM verification, instrumentation-preserving equivalence and broader client observations remain outside this result. Completed-operation grouping does not assign nonexistent result references to unfinished prefixes, and ghost computation history does not make discarded handles available. This is an author mathematical proof, not a mechanical certificate.
