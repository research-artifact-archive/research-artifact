# Shared-subtree cap-certificate checking

Before implementation outcomes. September8 08:48 JST. Keep fixed_order_profile_02 full Bellman checker and all ongoing/previous outcomes unchanged. This is a new checker for its existing persistent artifact, not a new constructor. It uses the already established concave cap characterization, whereas the previous checker directly checks Bellman equations.

For suffix f, integer slopes decrease to zero. For c>0,p>0 let a be the number of initial slope positions >=c. Define Delta(b)=c(b-a)-(f(b)-f(a)) for b>=a. The first protection threshold t is exactly characterized by t>a and Delta(t-1)<p<=Delta(t). The new slope at position t is z=(f(t)-f(t-1))+p-Delta(t-1), with 0<z<=c. Therefore Rf has the old slopes on positions1..a, then slope c on a+1..t-1, slope z at t, and the old slopes after t. Its finite support length is max(length(f),t). When p=0, Rf=f and threshold0. These conditions establish the all-budget cap function and its protection-first policy, assuming the concave cap theorem. Structural checking certifies exact decreasing positive runs and the implicit zero tail.

The checker independently queries f at a,t-1,t, obtains a by searching slopes, and verifies four new-root ranges: unchanged prefix, c plateau, z singleton, unchanged suffix. Contiguous ranges decompose into logarithmically many whole-subtree chunks plus at most two run fragments. Sequence equality expands chunks only when node identities do not already certify exact equality, compares run fragments with exact integers, and skips literally identical node IDs. No probabilistic hash is used. Forged metadata is rejected before identities are trusted; all child IDs must refer backward to an already checked immutable node.

Soundness does not depend on a fast traversal bound: fully expanding unmatched chunks still compares every finite slope exactly without expanding multiplicities. A checker arithmetic bound beyond output-sensitive visited chunks is not yet established. For generated AVL splices, the unchanged prefix/suffix share all but logarithmically many boundary nodes; whether the synchronized comparison is O(log n), O(log² n), or needs a different certificate proof is an author-check question. Do not report an unproved logarithmic verification guarantee based on timing. A malformed adversarial certificate additionally pays its supplied length and actual comparison work. Scope on prescribed branching orders remains restricted serial macros; forced-chain optimality uses the primitive abstraction.
