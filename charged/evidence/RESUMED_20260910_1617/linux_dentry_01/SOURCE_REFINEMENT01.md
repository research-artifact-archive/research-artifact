# Single-lock dentry path: candidate refinement and counted resources

Author derivation for Linux v6.12 adc218676eef25575469234709c2d87185ca223a. Scope is __dentry_path/dentry_path_raw, not getcwd, mount traversal, arbitrary filesystems or syscall latency. The first kernel guest infrastructure check ran only upstream examples (9 pass, 4 intentional skips); it is not research evidence.

The baseline first reads a stable even rename sequence, builds a pathname under RCU, releases RCU, and validates. On failure it rebuilds under the exclusive-reader side of rename_lock. Proposed cached fallback performs a second RCU traversal after obtaining a NEW stable even sequence s2, releases RCU, acquires the exclusive-reader lock, and compares the actual sequence with saved s2. Equality permits reuse of that prepared buffer. Otherwise it restores the original starting dentry and buffer descriptor and executes the same source body under the lock. The mode marker 1 must never be substituted for s2 in need_seqretry: that marker causes validation to be skipped. First-pass errors also remain tentative until validation.

Assume: the referenced starting dentry is valid for the call; buffers are private and have 1<=buflen<=INT_MAX; observed name lengths fit a nonnegative int; every relevant visible parent/name/length/content change participates in both rename_lock and its sequence updates; no sequence wrap occurs across a validation interval; source memory barriers and each optimistic pass's RCU lifetime apply; stable valid names can be read without a nofault-copy error; selected operations progress normally. Under no intervening sequence update, the buffered path/error belongs to the graph traversed during the call. Under exclusive protection, the fresh body belongs to its stable graph. Thus accepting only after the appropriate validation yields a linearizable raw dentry path or ENAMETOOLONG. A returned path is not promised to remain current after return. Prepublication initialization such as d_mark_tmpfile is not silently covered by the writer assumption; concurrently visible bypasses would falsify the source scope.

Let X denote first validation failure and Y denote second failure, when attempted. The traversals and body costs satisfy N=1+X+XY, W=c1+X*c2+XY*c3, L=XY*c3. Obtaining a new stable even s2 makes the first invalidating writer finish before the second preparation begins. Consequently two failures require two distinct global writer sections; X+XY<=min(B,2), where B includes unrelated rename sections and writes during preparation/waiting. Per-invocation bounds c_j<=u give W<=u,2u,3u for B=0,1,>=2 and L=0 at B<=1, L<=u otherwise. The native logical Q counts the first validation and the exclusive validate/recompute/complete block; Q<=2 is not a bound on all native API calls.

Set C=buflen-1 after the common NUL. Each successful name step consumes a slash, so even a torn/revisited path has at most C+1 name attempts. The sum of requested copy bytes and successful slash bytes is at most C; a failed nofault copy may additionally fill at most C bytes. We will retain all components: name visits, requested copy bytes, fault-fill bytes, slash bytes, protected counterparts, traversal invocations, validation blocks, global-lock entries, snapshot/dentry-lock operations, external-name reference increments/releases, and extra allocation bytes. A declared source-event scalar T=1+visits+requested_copy+fault_fill+slash per traversal therefore has u_T(C)=3*C+2. This is an explicitly chosen event resource, not an instruction/cycle/WCET model. A separate body-byte-demand bound is 2*C. Root C=0 still has constant work; its result is ENAMETOOLONG, while C>=1 permits '/'. Initialization/finalization bytes, guards, waiting, RCU and instrumentation are outside T and reported separately rather than inferred free.

For the stronger snapshot comparison, allocate stable name_snapshot slots outside the global lock. Under rename_lock take each ancestor name snapshot, then materialize outside and release every reference. Inline names copy inside protection; external names acquire references. A bounded 64-slot implementation may fall back to the ordinary complete body while still holding the lock when its workspace fills; it must include the discarded collection work and release costs. Allocation failure falls back to the baseline, not a new ENOMEM result. Do not move name_snapshot structs: inline pointers refer to their own slot. This is a stronger interface outside the whole-kernel lower-bound class. A successful saved global sequence check does not require a second full ancestor traversal, contrary to one sentence in the source-feasibility note.

Controls target ignored second validation, reuse of the old first sequence, failure to reset the buffer descriptor, and returning an unvalidated overflow. The latter uses a legal reparenting from '/bb/c' to '/aaaa': both fit C=7, but an old parent plus the new name can transiently appear as '/bb/aaaa' and overflow. A mid-body writer must run on a second CPU; the reader cannot sleep while holding RCU or a spinlock. A completion gate after rcu_read_unlock is used for ordinary endpoint invalidations.

No source-specific minimax lower bound or erased-observation result is transferred. Returning a path does not overwrite the live graph, so later inspections can expose writes. The declared fixed-cost class can prove robust-class exactness, but native costs vary and a stronger snapshot algorithm may improve multiple measured resources. Emulator elapsed time is environment cost only. Generic PATH_MAX ceilings may be loose; actual/ceiling ratios and every adverse result must remain visible.
