# Exact B1 optional-interval formulation

Author derivation and read-only author check; neither blind review nor a machine proof. Integer c_i>0,p_i>=0; arbitrary finite DAG. Let P=sum p. The B1 no-failure certificate in ../dag_hardness_01/PROOF_DRAFT.md has value C(pi,H)=max(sum_H p, max_fast_i(c_i+sum_protected_before_i p)). After the sole failure, all remaining jobs including the failed job finish FAST in the same order at zero further excess.

Use protection bits h, integer t/e in[0,P], K in[0,P]. Enforce e_i=t_i+p_i*h_i unconditionally. Positive protected intervals have fixed length p and presence h; impose NoOverlap. Zero-premium jobs are forced protected, retain all edges, and are points. Every edge u->v imposes e_u<=t_v. Impose sum p_i*h_i<=K and t_i+c_i<=K if h_i=0. Minimize K. The clock is accumulated protection premium, not wall time or baseline work.

A certificate of value at most P gives a feasible model by placing protected intervals consecutively and using preceding protected premium as each t. Zero-premium FAST jobs can first be protected without increasing value. Restricting K<=P loses no optimum because the all-protected order costs P. Empty inputs and P=0 cost zero.

Conversely, list positive protected intervals [s_j,f_j) in start order a_1,...,a_m. For every point i set r(i)=number of interval ends <=t_i. Output a topological ordering of points with r=0, then a_1, points with r=1, then a_2, and so on. Point-to-point edges imply nondecreasing r; protected-to-point edges put that point after the interval; point-to-protected edges put the point strictly before that interval's index. Protected-to-protected edges respect interval order. Thus the result is topological. A FAST point in block r has protected prefix sum_{j<=r} p_a_j <= f_r <= t_i (or zero when r=0), so its failure cost is <=K; total protection is also <=K. The extracted certificate costs <=K. The optimal values therefore agree; at OPTIMAL the extracted cost must equal K.

The implementation's normalization is equivalent to this block ordering. It moves a point strictly inside an interval to its left endpoint and sorts by normalized time, points before positive intervals, then a fixed topological rank. All points between consecutive interval ends occur in the same block; normalized times are monotone along point edges and a topological rank resolves ties. Points at an interval start precede it; points at its end follow it. The implementation independently scans its resulting permutation/modes and checks value<=K, with equality only when the solver reports OPTIMAL.

Naive sorting of unnormalized starts is invalid: independent (c,p)=(5,4),(3,1) admit h=(1,0), t=(0,1), K=4. Sorting a,b gives cost7; the required order b,a costs4. This is a counterexample to that unused extraction, not to the formulation.

The comparator uses pinned OR-Tools9.15.6755, one worker and fixed seed. Finite conformance checks agree on8,634 inputs but do not independently certify solver optimality beyond solver status and the theorem. Its int64 implementation is narrower than arbitrary mathematical integer encoding. No B>=2 extension or all-budget output is claimed.
