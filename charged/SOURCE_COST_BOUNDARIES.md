## Java completed-operation correspondence

[Full source argument](evidence/RESUMED_20260910_1617/java_refinement_01/OPERATION_TRACE_REFINEMENT_02.md) distinguishes live map values from permanent completed outputs, available handles from discarded ghost records, and a saved API output from a return-time map read. Its state relation uses an injective opaque-reference map that extends without changing existing identities, plus an ordered queue of already committed external assignments. At normalized boundaries, `decode(H.map)=apply(Delta,x)` and the concrete committed-write count equals the abstract count plus `|Delta|`. The queue replays assignments, not callbacks.

Whole pure computations are grouped only at completed-operation boundaries with their actual results and full work. Unfinished kernel instructions are not zero-cost stutters. Writes after publication but before API return may change the map while the wrapper saves the earlier completing output. A successful cheap conditional publication records its prepared output, whereas fresh/cached completion records the returned Value; conditional replace's boolean and internal oldVal are not completed outputs. The validation-only compute wrapper discards its extra mismatch value and returns a flag. Unwrapped APIs have different observations.

The argument assumes permanent keys, stable key methods, deeply immutable identity-equal values, tag/shape-preserving kernels and external writers, fresh own-key write identities, pure specified kernels, one foreground controller and normal progress of selected operations. It erases numeric allocation IDs, logs, clocks and scheduling diagnostics from the allowed controller/payload observations. The small native fixtures do not exercise tree/resize or the validation-only branch. Those cases use the pinned API/source reasoning; this is not a mechanically verified JDK/JMM theorem. The counter equations apply to the completed wrapper interface, not elapsed time. Lower-bound writes occur after action selection but before API entry, where no foreground monitor is held.

The pinned authored Java source is already in the earlier evidence set under `RESUMED_20260909_0056/charged_budget_blind_native_01`. ## Writer-maintenance04: the negative operational boundary

`valkey_writer_04` changes all designs to the same RESP writer and compares direct read-time hashing, compiled retained-refresh reading and writer-maintained digests. This is a new study, not a paired retiming of03's JSON writer. A trusted cooperating writer hashes each changed payload before atomically publishing its payload, incremented version and digest. The maintained publisher reads current digests and publishes them atomically. Initial digest construction, each writer hash, writer commands, and total wire bytes are included. Initial payloads are supplied at dataset creation; migration from an existing remote database and its initial payload download are unmeasured.

The complete grid is two scales × read counts1/8 × four update patterns, with six paired blocks,288 measured rows,48 warmups and12 smoke cases. All complete successfully. Total mixed-trace time includes driver encoding/control and writer work. Reader command-plus-hash time is a sum of measured spans, not all reader CPU. All-participant server maxima include writer and build commands but are not event-loop-stall bounds. No confidence intervals or significance tests were computed for these exploratory point estimates.

For all16 cells, maintained/compiled mixed-time geometric ratios are0.0633–0.6370 and all six blocks are faster; total wire is also smaller in every cell/block. Counted total work is equal in eight cells and smaller in eight. Maximum-server-command geometric ratios are smaller in14 cells and larger in two, so dominance on every resource is not claimed.

Against direct reading, maintained mixed-time geometric ratios are below one in all16 cells, but total work is lower in six, equal in two and higher in eight; wire is higher in all16. The exact work identity is `direct=R*P`, `maintained=P+U`, and `compiled=sum(reader work)`, whereU is changed-payload work. The equality `P+U=R*P` is a work boundary, not an elapsed-time crossover.

These cooperating writers satisfy the same published-digest completion contract and form a stronger alternative to reader-only repair. No source-backed application condition forbidding them was established. Accordingly this fixed-digest case does not close operational importance or support optimality over all system designs. Its earlier timing grids cannot be selected as favorable applications while discarding this alternative.
