Correctness evidence already observed:20,920 old-DP rows plus108 rational/long-horizon rows agree; all certificates and seven corruptions were checked. This is a new authored scale grid, fixed before execution. No native cost calibration or application sampling is claimed.

It returns the sorted component order, complete singleton coverage profile, optimal ratio, threshold policy parameters and lower/upper certificates. All generation, sorting, compilation and certificate checking occur in the process; report process wall time including interpreter/import startup and worker time separately. Peak RSS is observed using getrusage, not an enforced memory limit.

Paired grid: m in8,32,128,512; the same two weight patterns; q in2,4,8; mu in2,W. This is48 inputs, with compact and a stronger profiled Bellman comparator each run once:96 units. The comparator already uses H(k), eliminating a potentially unfair exponential dirty-set enumeration. It computes exact same root objective but returns no primal/adversarial certificate. Both use the same singleton profile, weights, baseline and call cap. A3second process cap applies to both. Compare ratios on joint successes and retain all one-sided successes/timeouts. Process order alternates by fixed input index; there are no repeated timing samples or inferential speedup claims.

Total denominator216 units. Total controller cap1200seconds, with child process-group termination on per-unit timeout and unstarted remainder retained if the total cap fires. SUCCESS/FAILURE/TIMEOUT/INVALID are disjoint executed outcomes; any unstarted units remain explicit. No outcome-triggered reruns or exclusions. Inputs and source hashes are written before the first child starts; raw stdout/stderr, return codes and receipt remain. All output paths are fresh. A result can support compiler scaling in this singleton model, not empirical prevalence, Roslyn mu or source runtime guarantees.
