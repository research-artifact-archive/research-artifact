# Independent-arrival Roslyn study: exploratory design before execution

Purpose: test whether the bounded retry mechanism changes native retry admissions, transformation counts, foreground completion, and background response delay when background requests are scheduled independently of foreground source hooks. Use the same pinned four-project/4,019-document source projection, the patch04 successor that passed error/event/immutable-snapshot regression, and an unmodified upstream DLL baseline. This is an authored asynchronous workload on one machine; it is not a production arrival trace, population estimate, WCET, human evaluation, or validation of fixed transformation weights.

Inputs fixed before first native execution: each fresh workspace executes 32 serial foreground revisions of the same linked source document and 64 independent background revisions of the selected unrelated source document. Texts and repository manifest are loaded and hashed before timed requests, and their setup time is reported. One producer enqueues all 64 requests at requested offsets j*d, d in {0,10,100,1000} microseconds, j=0..63. A separate worker executes that FIFO. The foreground starts at the same epoch as the producer. The epoch is fixed after both threads are ready, never based on a transform, lock acquisition or failure. Record intended arrival, actual enqueue, invocation, publication callback and return times, so scheduling/queueing delays and writes outside the foreground interval remain visible. Do not force a write in a prepare-to-lock interval or wait for a writer inside the foreground hook.

Six arms: unmodified baseline; instrumented original; two-mode r=0 and r=2; three-mode r=0 and r=2. In the primary timing run the study Hook is null. Native counters still instrument original/two/three, so baseline/original differences estimate this implementation's instrumentation impact. All arms record the same existing public event callbacks and immutable payloads; their observer overhead remains part of the measured workload. A separate bounded diagnostic run may enable source timestamps; label it separately and do not merge it into primary timing.

Run 3 fresh process forks per arm, each with 2 explicitly marked warm-up repetitions and 10 measurement repetitions of all four intervals, in fixed pseudorandom order; 864 total units, including 720 measurement and 144 warm-up. Fix process and unit order in TSV/JSON before execution. Retain every unit and all statuses; warm-up is a declared separate phase, not a post hoc exclusion. Bound each process to 180 seconds and the orchestration to 45 minutes (well before the 09:50JST stop preparation); terminate its process group on timeout. Any infrastructure failure is recorded; a corrected successor needs a changed input/implementation and an explicit reason.

Native semantic checks: all 64 background requests and 32 foreground calls return; the old/new public-event chain is continuous from initial to final Solution; each foreground publication atomically updates both linked documents in target-first order, preserves the latest background content in its old snapshot, and each background publication preserves the foreground revision; notification Document.Project.Solution matches event.NewSolution; immediate and queued payloads match; retained publication snapshots preserve their observed projections; final unrelated document SourceText identities/versions and metadata are unchanged. Record foreground publications and writer counts from the event chain, without treating CurrentSolution read after a call as its exact linearization snapshot. Record all exception/failure/timeout/invalid results. A separate checker validates input identity, denominators, publication transitions and inequalities from raw output.

Resource checks for completed normal runs: original Q=32+cheap failures; capped Q=32+cheap failures<=32+r, with cheap failures<=actual publications during the foreground interval and <=64. Three-mode inside transformations<=min(max(B_fg-r,0),32), where B_fg counts actual background publications in the entire foreground interval; two-mode inside<=32. Total outside+inside transformations and per-arm call counts are reported, not converted into fixed weighted work. Use realized counts and arrival/return delays alongside nominal load; different policies can change actual interleaving without invalidating an adaptive adversarial-cap theorem.

Analysis: report every interval and arm, per-fork summaries and pooled medians/p95 only with replication units stated. Compare foreground batch duration, background end-to-end/queue/service delay, and instrumented original versus baseline. Avoid a selective aggregate speedup or interpreting empirical tails as guaranteed bounds. If few collisions occur or no practical timing advantage appears, preserve that adverse result and lower the empirical importance claim; do not retune intervals to make the same experiment favorable. A substantive source-contract result remains distinct from performance value.
