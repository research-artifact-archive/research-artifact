# Finite witness adapter v1

`witness.schema.json` is the structural schema. `WitnessDriver.java` reads explicit finite models and calls only the fixed E1 JAR (`ff1e6b176f004ea85f1e99690a90388a6a4d24f44cd8d8e636fcd9337dcf67d5`) for Post, goal, merging, synthesis, endpoint validation, certificates, and Link. It is compiled to classes, not a replacement solver JAR.

Top-level fields are `schema: "fg-ducs-witness-v1"`, `id`, `family`, `parameters`, `ordinary`, `controllable`, `components`, `requirements`, `precedence`, and `endpoints`; optional `metadata` holds interpretation and provenance.

- Every LTS is `{states:[string], initial:string, edges:[[source,action,target]]}`. State and edge references must be declared. Duplicate states/edges are rejected. A local component not owning an ordinary action stutters under the unchanged E1 product rule.
- A component is `{id, old:LTS, new:LTS, transfer_action, transfer:{oldState:[newState,...]}}`. Fine inputs have unique update actions. Generated group contracts declare top-level `generated_contract_mode` as `transfers`, `boundaries`, or `both`, and may share same-kind update actions. The small same-package `GeneratedContractInput` adapter invokes the existing E1 package-private `builder.mergedContract("generated_"+kind,false)` construction hook, followed by exhaustive reachable endpoint enumeration. It changes no Post, goal, solver, merge algorithm, or JAR/source. This internal construction API use is explicit; E1 `withContractMerge` on the fine input is the independent all-group comparison. Missing old-state entries have empty transfer domain; targets may be nondeterministic.
- A tester is `{states,initial,errors,alphabet,changes:[[source,action,target]]}`. The default is stutter; changes override it. Error states must remain in the error set. Tester symbols outside its alphabet stutter under E1. No tester can inspect the physical successor of an action directly.
- Each requirement has `id`, `role` (`old`, `new`, or `interval`), and `tester`. Old/new roles add `update_action` (stop/start). New/interval roles add `activation:{entries:[{physical:[["OLD"|"NEW",localState],...],tester_state,residual_state}],residual?:tester}`. Entries explicitly give the finite guard and initializer. Omitted residual uses the same automaton as the tester; an explicit residual is independently checked for bad-prefix-language equivalence by E1. Old requirements inherit endpoint states. Interval requirements activate at hotSwapIn and have no boundary event.
- `precedence` contains strict `[earlier,later]` event pairs. E1 merging rejects collapsed strict edges or noncommuting grouped monitor observations; these are invalid contracts, not LOSS results.
- Each endpoint has `lts`, `controller`, and `projection` keyed by endpoint state. Projection values are `{physical,testers}` for old and `{physical,testers,goal_id}` for new. `testers` maps only the relevant old/new requirement IDs. The new endpoint adds `loadable:[endpointState]`. The Java adapter uses exhaustive reachable endpoint enumeration and E1 EndpointContractValidator. An independent Python checker must also reconstruct plant × controller × endpoint requirements and compare the supplied graph/projections. Controller data is for that independent product check; Java validates the declared endpoint graph directly.

Compile with JDK 17:

```text
javac -cp E1.jar -d common/build/classes common/WitnessDriver.java common/GeneratedContractInput.java
java -Xmx32g -cp common/build/classes:E1.jar WitnessDriver --input INPUT.json --merge none --solver lazy --output RAW/result.json
```

All command options take a value. Solvers are `lazy` or `direct_full`; merges are `none`, `transfers`, `boundaries`, or `both`. Optional `--compare-input FILE --compare-merge MODE` exhaustively checks equal initial configurations, safe/goal classifications, controllability, and all reachable Post sets before solving. It is a preflight check with a one-million-state guard, not a replacement solver.

The process returns 0 for checked WIN, 2 for checked LOSS, and fails for invalid input/checking. Both `result.json` and sibling `certificate.json` are create-only. Each trial must have its own directory. Results record observed states, queries, rank/losing-region size, preparation, synthesis, and checking/Link seconds, endpoint/certificate/Link status, input SHA, and certificate SHA. `enabled_buckets` counts distinct queried state/action pairs with nonempty Post during synthesis; `materialized_transitions` counts their outcomes. These differ for set-valued transfers. The counting wrapper delegates all semantics, ordering, and goal hints to E1.

`certificate.json` contains `decision`, fixed `jar_sha256`, and `states:[{id,physical,testers,pending,initial,safe,goal,rank?}]`. A WIN also stores `strategy_edges:[[sourceId,action,targetId]]`, including every adversarial outcome in each returned policy bucket. The rank is a certificate completion bound, not a claimed optimum. A LOSS stores its discovered certificate region, not the maximum losing region of the whole game. `loss_summary` in the result reports counts and at most three initial-root examples with complete enabled buckets, outcomes in the certificate, unsafe outcomes, and up to three unsafe successor examples per bucket. This is local closure evidence, not a unique causal explanation.

Common Lazy settings match the earlier CLI: lazy controllable buckets, guided state/query limits zero, and endpoint-guided action ordering. Direct-Full uses the same oracle and constructs its full reachable game. No fairness assumption is introduced by the adapter.

Design-only correction before any solver trial: shared update labels were initially described as a normal public-builder input, but source inspection showed E1 rejects duplicates in mode none. A public product-component draft was compiled but never executed and is retained under design_archive/public_product_draft. The registered final choice uses the small same-package construction helper above, preserving n physical components and their ordering. Generated coarse inputs run with CLI --merge none; a second E1 merge on an already-generated contract is intentionally rejected.
