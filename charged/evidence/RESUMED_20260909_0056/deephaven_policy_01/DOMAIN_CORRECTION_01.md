# Domain correction after the source review

This addendum corrects the saved pre-run PLAN; it does not replace its original bytes or any result. It applies to the same hooks reused in deephaven_compiler_import_01. See DEEPHAVEN_RESOURCE_AUTHOR_REPORT_08.md for the complete author source analysis and its limitations.

The PLAN statement that all policies retain the original nested-snapshot semantics is false for an installed target observer. A nested target scope throws IllegalStateException. A non-target nested scope can leave the outer binding active and mix inner work into its counts; an inner acquired lock can also invalidate the protected-work accounting. The normal-domain contract excludes both forms of nesting. The four upstream regression tests ran with the observer inactive and therefore do not verify nested behavior under an installed study policy.

The native matrices use a fresh executor thread that is neither the update thread nor already holding a graph lock. Source and key tables are refreshing; the initial graph is Idle; there are no external writers or clock resets. Source/key row sets and structural columns are immutable, source partitions are compacted single intervals, and only Sentinel/same-valued Action updates occur. Target functions, controls and user data are those fixed in the source packet. No static, already-locked, custom-control, UDF, sorting, filtering or nested paths are admitted by the claimed cost contract.

Updates in these first two matrices happen at the BEGIN observer and the observer waits for the requested action to finish before invoking the actual function. FULL/COMPLETE therefore finish the notifications/cycle before body processing starts; START changes the logical clock but writes no data. These runs exercise real inconsistencies within the native read-clock-to-validation interval. They do not yet exercise an update after a prefix of body processing. The all-prefix resource argument for this restricted driver relies on the fixed source structure and operation counts; the observations themselves do not prove it.

NoSnapshotAllowedException forces protection without a compiled decision and can violate the DP cap. NULL usePreviousValues choices increment native attempt count without a body or a budget decrement; the current checker will reject its later attempt-count mismatch, and custom NULL loops are not runtime-bounded. A writer-request timeout does not cancel its queued request; a later update/retry can escape the normal synchronization argument. The checker rejects END!=1 and other irregular traces, but post-outcome rejection is not runtime fail-stop protection. No unconditional guarantee after such an error is asserted.

Under the fixed normal domain, the source analysis supports K<=4, V<=176 for every body prefix and FK+FV<=2q over sequential K->V. It also derives the normal complete-body counts K4 and V104 from the actual directive order, traversal and requested columns. Generalizing that tighter cap to body-internal update/interruption points is a separate investigation. These are selected logical-operation bounds, not complete CPU, allocation, waiting or end-to-end runtime bounds.
