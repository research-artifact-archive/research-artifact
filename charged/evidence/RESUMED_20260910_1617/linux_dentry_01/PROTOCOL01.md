# First exploratory Linux source integration matrix, fixed before execution

Route SCIENTIFIC. This is the first actual Linux execution of these research cases. The preceding KUnit example run established infrastructure only. Version 01 uses Linux v6.12 at adc218676eef25575469234709c2d87185ca223a, in an ARM64 QEMU TCG guest inside the task-owned unprivileged Docker container. The host kernel and its filesystem implementation are not modified. This is a source/event and semantic experiment, not a native performance benchmark or a workload prevalence study.

## Questions and limits

Can an additional freshly stamped traversal outside `rename_lock`, followed by reader-exclusive revalidation of that exact stamp and conditional recomputation, preserve `dentry_path_raw` output while meeting the bounded body-work corollary in SOURCE_REFINEMENT01.md? Does it move the first-conflict traversal out of protection? What does a stronger immutable-name snapshot interface cost instead? The conjectured result applies to body source events with participating global writer sections, no sequence wrap, valid inputs and bounded buffers. It does not claim elapsed-time/SLA guarantees, whole-kernel instruction bounds, kernel-wide deployment correctness, or optimality against the stronger snapshot interface. No performance, novelty, importance, or acceptance judgment follows merely from matrix success.

## Fixed input denominator and execution

INPUTS01.json fixes all 1,540 rows in order: 8 path families × 6 buffer capacities × 8 schedules × 4 policies = 1,536 valid rows, then 4 deliberate defect controls. Families include the root, 1/4/16/80 components, 39/40/127/255-byte names, a transient overflow witness, and a shrinking-path witness. Capacities 1,2,8,32,128,4096 include the NUL byte. Names of length 39/40 straddle the architecture's verified 40-byte inline storage. The 80-component family can exceed the snapshot's fixed 64 slots.

The policies are upstream retry-then-lock; cached fallback; always-locked; and immutable-name snapshot with 64-slot capacity. Each fixture uses real dentries and inodes mounted on an author pseudo filesystem. A CPU1 kernel thread executes actual `lock_rename`, `d_exchange`, and `unlock_rename`; the reader is pinned to CPU0. Schedules request no write, first validation write, both validation writes, unrelated writes, pre-invocation plus first write, a write between loading the first parent and reading its current name, ancestor writes, or a write after return. Unreachable hooks are retained and reported as unissued. Different policies may finish before a later schedule hook. Cross-policy numerical comparisons must use actual issued writes and identify the common schedule, not silently assume equal B from the profile name.

Endpoint gates are outside RCU and may wait. The mid-body gate spins on an acquire/release flag with a three-second cap without sleeping inside RCU. It relies on the two online guest CPUs. No timing measurement excludes these synthetic waits to imply a native speedup. Fixture allocation/setup errors, writer timeouts, canary damage, or reference-oracle errors invalidate the environment for further rows; the remainder is explicitly NOT_EXECUTED. An isolated policy/control discrepancy with healthy fixture continues through the full matrix. Build/config/run failures, all logs, missing rows and all outcomes are retained. There is no exclusion, unrecorded rerun, or success-conditioned sampling. Corrections require saved old bytes, a reason and a new execution version. This first matrix is exploratory, not retrospectively preregistered final evaluation.

## Source integration and metrics

The original static loop is factored into `__dentry_path_body` with the original operations and order. Upstream guard/retry behavior remains the baseline. Test-only hooks record each attempted name, requested copy length, fault-fill length and successful character write. Both the baseline and candidate use this same body. This is not a binary-identical upstream build; independent output checks and a saved patch make the instrumentation inspectable.

For each traversal, T = 1 + name attempts + requested copy bytes + fault-fill bytes + slash writes. If C = capacity−1, the source-level ceiling is u_T(C)=3C+2; byte demand is at most 2C and name attempts at most C+1. Each component is retained separately, with an inside/outside-protection bit. NUL/root postambles are reported separately. Q counts logical validation/completion operations, not all native API or lock calls. Actual reader-exclusive acquisitions and RCU sections are also counted. B counts actual global writer critical sections during this invocation, excluding the separately reported pre-invocation and late writes. Unrelated renames consume B because the real sequence counter is global.

The candidate must have Q≤2, N≤1+min(B,2), T≤(1+min(B,2))u_T(C), and L_T=0 for B≤1 and L_T≤u_T(C) otherwise. Upstream must have Q≤2, N≤1+min(B,1), and L_T=0 for B=0, at most u_T(C) otherwise. Always-locked has one body and one completion. Every recorded traversal must satisfy the local bound. These are upper bounds and may be loose on short paths or early overflow; achieved maxima are not the mathematical supremum.

The stronger snapshot captures parent names under `rename_lock` and each native dentry lock, then materializes after release. Names occupy a stable heap array; inline self-pointers are never moved. A slot-capacity shortfall recomputes the upstream body inside the same guard, retaining all discarded capture cost; allocation failure falls back to upstream, not a new ENOMEM return. Allocation bytes, guarded snapshot node steps, takes/releases, inline-copy bytes and external-name reference increments/decrements are reported separately, including all abandoned captures. Body-only L_T must not be presented as its total protected work. No whole-resource dominance is inferred by dropping these extras. This matrix does not inject allocation failure or nofault-copy failure; coverage is explicit.

## Correctness and defect controls

The first oracle constructs the expected pathname from fixture names, exchange parity and exchange kind without traversing live dentries or calling any tested body. It predicts ENAMETOOLONG exactly from path length and buffer capacity; successful paths must match full bytes, NUL termination and the returned offset. A second quiescent call to instrumented upstream with all hooks disabled must agree. FNV-1a hashes are provenance/convenience fields; full-string comparison is performed in the guest. Sixteen-byte canaries surround the output buffer. The late-write profile verifies that returned private-buffer bytes persist after a subsequent rename. Pre-writes are excluded from B but included in the semantic oracle's exchange parity.

The four fixed controls omit second-stamp validation (stale output), reuse the first stamp (B=1 protected-work violation), omit buffer restoration (persistent stale overflow), and return overflow before validation (transient mixed-path overflow). A control succeeds only if its intentionally wrong policy is detected by output or resource checks while environment/oracle/canaries remain healthy. Failing to detect a control is a failed result. These controls are not claims about bugs in upstream Linux.

## Records and resource caps

The start receipt hashes inputs, source implementation, generated patch, config, protocol and runner before installation/execution. Full kernel build output, `.config`, KUnit JSON and unfiltered serial test log are copied out even after failure when available. DPBODY, DPROW and DPAUX are separate bounded printk records so large rows are not silently truncated. Offline validation independently checks the fixed row set, joins all auxiliary/body records without dropping failures, recomputes fixture hashes and resource sums, and scans raw kernel output for warnings/errors. A KUnit pass with missing/truncated rows or lock diagnostics is not a clean result.

Build plus execution is capped at 3,600 seconds, guest test execution at 600 seconds. Timeout stops the task-owned container; no host-wide cleanup is performed. The global 2026-09-11 09:50 JST closeout and 10:00 JST stop remain binding. The container's independently bounded lifetime ends earlier unless explicitly extended for authorized remaining work.
