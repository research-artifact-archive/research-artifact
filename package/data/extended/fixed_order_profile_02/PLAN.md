# Persistent arbitrary-order construction, exploratory implementation

SCIENTIFIC route. September 8, 2026, before implementation outcomes. This version implements the previously author-checked derivation in fixed_order_profile_01. The inherited concave cap operator is not claimed as new. The concrete question is whether arbitrary prescribed serial orders, and hence DAGs with a unique topological order, can be compiled using persistent run trees without numerical budget expansion or quadratic copying of all suffixes.

Use immutable AVL nodes with slope/count, subtree length/area, height and boundary slopes. Each suffix update splits before slopes below c, searches accumulated deficit to premium p, replaces the consumed interval with a c plateau and at most one partial step, and shares the unchanged prefix/suffix. Prices are integer c>0,p>=0. The zero tail is implicit. Serialization stores the shared node DAG and all suffix roots plus policy thresholds. Construction is intended to use O(n log(n+1)) arithmetic operations and allocated nodes, independent of numerical budget/price magnitude. Do not infer a matching verification bound: the independent full Bellman scan planned here streams every suffix profile and is O(n^2) in the worst case, with output-sensitive counts reported.

Implementation development and falsification checks will be frozen with exact input/source/runtime manifests before outcome execution. All failures, invalid inputs, timeouts and unstarted units remain. Corrections get a separate version/run with the preceding results unchanged. Differential checks use an independently coded scalar recurrence and existing generic all-budget curves on small forced chains; independent all-budget Bellman checking and selected malformed/corrupted certificates validate stored policy attainment. Large inputs include increasing, decreasing, nearly increasing with local inversions, oscillating and deterministic random prices, with small and wide-binary families; caps and exact units are fixed before measurement. No unchanged adverse unit is rerun to improve its outcome.

This is exploratory engineering and an algorithmic boundary, not an application evaluation, independent blind review, or novelty/acceptance certification. The primitive abstraction supplies forced-chain optimality. For an arbitrary prescribed topological order on a branching DAG, only the restricted serial-macro family is optimized; do not assert that all interleaved primitive programs constrained merely by commit order have the same optimum.
