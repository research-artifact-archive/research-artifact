\subsection{Why the Generated State Represents the Contract}
\label{sec:contract-adequacy}
A \emph{local update history} records an old entry and event/outcome sequence of the supplied operations (TA~\ref{ta:source_synthesis}); the proposition establishes state sufficiency, and Section~\ref{sec:monitor-meaning} addresses requirement interpretation.

\begin{proposition}[Contract/game correspondence]
\label{prop:contract-adequacy}
For an eligible contract, histories with the same component tuple, active monitor memories and unexecuted commands admit the same next events and outcomes, safety status and handover targets. Folding histories into these states gives a label- and outcome-preserving correspondence with game paths. A history-dependent policy satisfying the source obligations exists exactly when a winning game policy exists.
\end{proposition}
\begin{proof}[Proof outline]
Every source operation folds to exactly its game successors, preserving labels, outcomes and safety. Induction lifts paths and policies both ways; the finite reachability attractor supplies a state-based winner (full proof: TA~\ref{ta:source_synthesis}).
\end{proof}
