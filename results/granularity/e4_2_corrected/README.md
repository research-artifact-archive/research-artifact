# E4-2: corrected representation of the fixed full Cell ring
The initial series is preserved in sibling `../e4_2/`: all 45 trials, immutable input/source/class manifest, and raw logs remain unchanged. It yielded 9 WIN, 6 LOSS, and 30 input ERROR records. At n=5..10 the fifth normal holder name E collided with the interval monitor error name E, so every affected cell failed input activation validation before entering the solver. The initial static checker omitted the required name-uniqueness/disjointness check.

This separately preregistered corrected series repairs only that representation error. For n>=5, the interval monitor error name, its final state declaration, erroneous transition targets, and corresponding descriptive text become ERR_ONE. Normal holder E and its normal transitions remain E. The n=2..4 JSON inputs are byte-identical. Physical LTSs, transfer relations, old/new requirements, initialization values, precedence, endpoints, fixed E1 JAR, solver settings, job order, limits, and number of trials are unchanged. This faithfully implements the preregistered n normal holder states plus one distinct error state; it is not selection by an observed synthesis outcome. There were no n>=5 solver outcomes in the initial series.

Before the corrected measurements, `validate_correction.py` checks the exact limited difference, n2..4 byte identity, unique monitor states, separation of every holder from the error, and all interval initializer states being non-error. `validation/correction_scope.json` records the result. An independent agent also audits the difference before freezing. The same 45-cell schedule is then run once in full, including n2..4; initial timings/results are retained separately rather than pooled or selected.

This is a constructed witness family, not an application benchmark or prevalence estimate. Only this directory is created/changed. `gen_cell_ring.py` generates physical finite LTSs and finite contract data for n=2..10 without reading results. Existing inputs are never overwritten with different bytes. One product travels around the ring; a station can transfer only while empty. The original Cell's one old requirement, one new inspection requirement, one interval holder monitor, and strict start-before-stop edge are retained. Thus boundaries has only one start and one stop; its merge is structurally vacuous.

`CellRingDriver.java` is an input adapter, compiled against the immutable E1 JAR with SHA-256 `ff1e6b176f004ea85f1e99690a90388a6a4d24f44cd8d8e636fcd9337dcf67d5`. No solver JAR is built. Post, Goal, contract merging, Lazy, Direct-Full, certificate verification, and linking use E1 JAR implementations. Lazy has guided state/query limits 0/0, lazy controllable buckets true, endpoint_guided action ordering. These properties are read by the same E1 solver/oracle as the existing CLI. The input adapter skips CLI parsing/coverage machinery and has different preparation work; its timings are not comparable to prior CLI or Xeon results. It does not implement a substitute action ordering.

The inspector initializer is materialized over all 4^n tagged physical tuples. In n=2 its otherwise unreachable zero/multiple-holder completion is identical to the preexisting Java fixture. S1 specifies only the eight versioned one-product tuples. Product conservation proves that the extra entries are unreachable and cannot affect a decision or rank. The input preparation cost is recorded separately and is included in the whole-JVM timeout.

`FixedCellReference.java` copies the preexisting full Cell problem fixture literally, then independently supplies its old/new controllers and closed loops. `verify_cell_ring.py` checks n=2 primitive equality against `experiments/paper_witnesses/check_witnesses.py`, the fixed full Post census, and conservation for all n and version masks. `validate_generated_endpoints.py` independently reconstructs every declared endpoint product. The n=2 Java preflight compares all finite primitives, the full reachable Post closure (including unsafe/goal successors), independent checker Post/Goal, endpoints, decision, returned root/max ranks, and states/queries under each same solver setting. It does not compare returned ranks with a chosen constructive upper bound or force any expected result.

Before any solver preflight, `python3 run_cell_ring.py freeze` saves source/generator/input/class/JAR hashes and the full ordered 45-job schedule in `build/frozen_manifest.json`. Run `python3 run_cell_ring.py preflight` once; after PASS, `bash run-e4-2-mac.sh` runs n ascending, then (none Lazy, transfers Lazy, boundaries Lazy, both Lazy, none Direct-Full). Each cell has one trial, heap 32g, whole JVM limit 1,200 seconds including preparation and checking/linking; JVMs are serial. No retry or outcome-dependent input/order change. Inputs, classes, and JAR hashes are rechecked before each job. Job starts stop at 17:39 JST to leave the whole 1,200-second allowance before 18:00; unstarted jobs remain NOT_RUN_DEADLINE. Timeouts/errors are retained with stdout/stderr and invocation/completion records. Output directories and result files are create-only.

`summary.csv` columns: n, merge, solver identify the fixed cell; status is WIN/LOSS/TO/ERROR/NOT_RUN_DEADLINE; decision exists only on solver completion; states_discovered/states_expanded, successor_queries, and materialized_transitions are unmodified solver statistics. enabled_buckets equals materialized_transitions for this deterministic singleton-Post family. worst_completion_rank is the maximum rank in the returned reachable winning certificate, equivalently the maximum root guarantee (not asserted optimal). losing_region_states is the returned losing certificate region within discovered states, not a maximal whole-game losing region. certificate_states and linked_states count returned certificate and linked controller LTS states. preparation_seconds, solver_seconds, checking_and_link_seconds are separate in-process clocks; wall_seconds includes the entire JVM. exit_code, input_sha256, result_file give provenance. Null/blank fields are unobserved, never estimates. Mac timings are reference only. JSON records also retain root ranks, full command, timestamps, and checker outcomes.


After all 45 cells finish, `python3 analyze_results.py` verifies the raw/CSV records and frozen hashes and creates `summary_wide.csv`, `table_s1_cell_ring.tex`, `table_s4_cell_ring.tex`, and `validation/final_series_audit.json`. The S1 table reports the four Lazy contract variants; S4 reports none Lazy versus none Direct-Full. Both retain non-completions. The initial failure series is explicitly noted in the table sources and must remain disclosed with corrected results. No data is averaged across the two series. Source fragments are supplied for FSE-main; no primary paper file is edited.
