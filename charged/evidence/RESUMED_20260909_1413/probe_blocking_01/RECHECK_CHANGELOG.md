# Post-outcome checker strengthening, no measurement rerun

Author-side inspection found that checker v1 accepts overlapping successive job probes with internally consistent sums, and negative setup/kernel-out/process times. These corruptions are absent from the original raw records. V1 code and its PASS receipt remain unchanged as historical output. V2 adds cross-job completion-before-next-callback order, nonnegative timing fields, process chronology, and total interval containment, with five additional counterexamples. It rechecks the same5760 records and recomputes the same descriptive summary. No sample is excluded or repeated.

The checker was written after the native execution and was not part of the pre-execution input hash. The protocol and analysis choice predate timing, but this is not a fully preregistered experiment. Java argv used PATH resolution; executable/version are recorded separately after execution and the earlier session's java-version observation is corroborating evidence rather than a pre-execution binary hash. setup_ns starts in the Run constructor body, after Java field initializers; it is partial setup cost. Per-fork process duration includes JVM startup, all warmup/measure invocations and serialization; foreground_ns includes the probe hooks but excludes setup. No full per-invocation cold construction time is claimed.
