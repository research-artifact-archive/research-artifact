\title[Staged Updates between Verified Controllers]{Synthesizing Staged Updates between Verified Controllers}

\author{Anonymous Author(s)}
\renewcommand{\shortauthors}{Anonymous Author(s)}

\begin{abstract}
Changing several components or requirements together can remove a state needed for update completion; separating them can expose harmful behavior. Fine-Grained Dynamic Update Controller Synthesis (FG-DUCS) generates the intervening game from local transfers, requirement lifetimes and initial obligations between fixed verified controllers. Winning policies keep active monitors safe, finish from every old entry under every modeled outcome without fairness, and restore the selected endpoint continuation. Our second contribution identifies when update granularity can change. A local transfer preserves global uncontrollable quiescence in every synchronous context exactly when it offers no new uncontrollable label and removes no blocker; with additional outcome, monitor and precedence conditions, this suffices to expand a winning batch policy into individual commands. A capacity theorem and analytical counterexamples delimit these conditions. Constructions separate both directions, whereas none of \VThreeEOneTrials{} inherited comparisons changes its decision; ten saved-policy expansions check the construction on a restricted family. An implementation using established lazy reachability-game exploration decides \LazyDecisions{} of \ApplicationContracts{} adapted contracts within 1,200~s. The scope is finite maintenance: commands require global quiescence, and neither continuous service nor elapsed-time bounds are guaranteed.

\end{abstract}

\section{Introduction}
\label{sec:introduction}
Software controllers coordinate components whose capabilities and required behavior evolve. In a production-cell example, replacing a polishing tool with a painting tool changes available commands and processing order; partially processed products require a transition policy~\cite[Sec.~2]{Nahabedian2020}. In robot patrol, engineers revise locations to avoid and revisit while preserving obstacle avoidance~\cite[Sec.~1.1]{Amram2022GR1DynamicUpdate}. Such changes make the transition itself a verification task in software evolution: intermediate configurations and active obligations need justification as well as the endpoints. We study this task for finite maintenance that permits service pauses, using local change descriptions and explicit choices of update granularity.

A controller update must coordinate component replacements with requirements that change at different times~\cite{Cheng2009SASRoadmap,Andersson2013SEAMSProcesses,Ghezzi2012DynamicScenarioUpdate,PanzicaLaManna2013CorrectnessDynamicUpdates}. Correctness of the old and new controllers does not establish a safe transition~\cite{Nahabedian2020,Amram2022GR1DynamicUpdate}. Its \emph{granularity} matters too. Replacing both Cell stations together is impossible because one holds the workpiece (Section~\ref{sec:example}); replacing two components of another model separately exposes an uncontrollable (UC) loop absent from both endpoints (Section~\ref{sec:serialization}). Neither grouping nor separating operations preserves feasibility in general.

Dynamic Update Controller Synthesis (DUCS)~\cite{Nahabedian2016SEAMS,Nahabedian2020} and generalized-reactivity(1), or GR(1), updating~\cite{Amram2022GR1DynamicUpdate} already generate update control. FG-DUCS fixes both endpoint controllers. Two design questions remain after their verification: which local inputs determine the intervening game and which choices synthesis makes (C1), and when a winning batch policy can be expanded into individual commands (C2). We answer the first and give sufficient conditions and obstructions for the second, using established reachability-game synthesis.

\Needspace{3\baselineskip}
\par\noindent\textbf{C1: A local contract for staged handover (Sections~\ref{sec:formalization}--\ref{sec:interpretation-execution}).} The modeler supplies transfer outcomes, requirement lifetimes and initial obligations; the generator supplies mixed configurations, guards and handover tests. Synthesis chooses coordination and a handover target from every reachable old state. Winners keep active monitors safe and finish under all modeled outcomes without fairness. They restore the selected endpoint's permitted behavior, which safety requirements alone need not preserve. We distinguish this game guarantee from requirement interpretation and platform execution.
\par\noindent\textbf{C2: Conditions for changing update granularity (Section~\ref{sec:granularity-analysis}).} A batch removes the states between its members, changing the update contract. Given a winning batch policy, sufficient conditions construct an individual-command policy without solving the fine game again, preserving completion and the selected endpoint. An exact test characterizes UC quiescence preservation in every synchronous context using local alphabets, enabled UC labels and transfer pairs. Additional outcome, monitor and precedence conditions protect intermediate states. Obstructions and a capacity threshold rule out specified merges; failing the test leaves feasibility open.

The intended use is checking a finite maintenance plan before execution. Work may pause. Every command and handover requires global UC quiescence: no environment event that control cannot disable is enabled. The guarantee counts events, not elapsed time; persistent UC activity can prevent completion.

The evidence has distinct roles (Section~\ref{sec:evaluation}). Constructed mechanisms and analytical counterexamples explain both granularity directions; none of \VThreeEOneTrials{} inherited comparisons changes its decision. These establish possibilities, not prevalence. Saved policies check serialization on one restricted family; game and source checks test selected guarantee layers; \ApplicationContracts{} adapted contracts compare exploration costs within one solver.

We created the public replication package~\cite{FGDUCSAnonymousArtifact} for this research. TA (Technical Appendix) and S1--S5 denote the accompanying \emph{Supplementary Material}; Data Availability identifies its matching version and source.

\section{Why Updates Need Separate Component and Requirement Choices}
\label{sec:example}\label{sec:mechanism-boundary}
\label{sec:cell-example}
Cell motivates transfers and initial duties; Policy motivates separate requirement boundaries.

\subsection{Cell: Moving Work before Replacing a Station}
Our constructed \emph{Cell} example has two stations $A,B$ and exactly one workpiece~\cite{Lewerentz1995ProductionCell,Nahabedian2020}. A station can be replaced only while empty. The old controller moves the workpiece between stations and forbids inspection. The new controller requires inspection at $B$ before departure. Both endpoints are verified, yet simultaneous replacement is impossible: one station always holds the workpiece.

\input{figures/cell_story_visual.tex}

\paragraph{Coordinating moves and changing duties.}
Figure~\ref{fig:cell-story} shows the policy from both old states, called \emph{entries}. Each path replaces the empty station, moves the workpiece, and later replaces the other station. The input requires new-start before old-stop, preventing an unprotected gap; synthesis chooses the remaining order. If $B$ holds at new-start, inspection becomes pending; it must wait until old-stop removes the ban. Starting its monitor---the automaton tracking the new rule---clear would silently discard this duty.

The first path inspects before handover; the second starts with $B$ empty and needs no inspection. Both reach allowed new closed-loop states with inspection clear: $z_A$ holds at $A$, and $z_B$ at $B$. A nonnegative \emph{rank} decreases on every arrow, excluding safe but endless inspection.

\paragraph{What synthesis chooses.}
For Cell, the modeler supplies transfer relations $g_A=g_B=\{(e,e)\}$, where $e$ means empty; new-start precedes old-stop; the new initializer installs pending iff $B$ holds; and the loadable targets are $z_A,z_B$. Synthesis chooses the remaining sequence and target. All Cell events are controllable: $m_A,m_B$ move to $A,B$, $j$ inspects, and $\rho_A,\rho_B$ replace a station. TA~\ref{ta:cell} gives the complete input and proof.

\Needspace{10\baselineskip}
\subsection{Audit and Role Lifetimes}
The constructed \emph{Policy(2)} example has two old/new requirement pairs: audit and access role. Audit coverage must persist, while old and new roles must never overlap, requiring opposite boundary orders:
\[
\begin{array}{r@{\quad}c@{\;}c@{\;}c@{\;}c@{\;}c}
\text{Audit:}&\text{old only}&\xrightarrow{\text{new-start}}&\text{both active}&\xrightarrow{\text{old-stop}}&\text{new only}\\[2pt]
\text{Role:}&\text{old only}&\xrightarrow{\text{old-stop}}&\text{neither active}&\xrightarrow{\text{new-start}}&\text{new only}
\end{array}
\]
The role gap is declared by the interval requirement, rather than forced by access rules alone. The new audit monitor starts unlogged and requires a log before service. Each endpoint alternates its own log and service, permitting only its own access role. With an identity transfer, the saved policy obeys these opposing orders and reaches a compatible new endpoint from both old states in at most six events.

Merging starts and merging stops makes the first start overlap roles and the first stop remove audit coverage. Ordinary events and transfer cannot change the active rules, so neither entry has a completing merged policy. TA~\ref{ta:policy_interpretation} gives the complete finite input, policy and losing closure.

\section{Defining an Update Contract}
\label{sec:formalization}
\label{tab:contract-inputs}
The modeler supplies local behavior, transfers, monitored duties with activation states, fixed controllers and precedence; FG-DUCS generates the mixed configurations, commands, guards and handover tests of a global game, in which synthesis selects controllable choices while retaining every UC event and outcome.

\Needspace{9\baselineskip}
\paragraph{Scope and premises.}\label{sec:scope-premises}
Five premises define this maintenance setting. \textbf{(i) Service may pause:} update control replaces old scheduling and preserves only declared monitors, not old liveness; duties needed throughout belong in interval monitors. \textbf{(ii) Global UC quiescence:} commands and handover require no enabled UC event in the active-component product (Equation~\eqref{eq:nonpreemption}). This differs from transaction-based quiescence~\cite{KramerMagee1990Quiescence} and tranquility~\cite{VandewoudeEtAl2007Tranquility}. \textbf{(iii) No fairness or command priority:} persistent UC activity can prevent completion. \textbf{(iv) Event-count guarantee:} completion has no elapsed-time bound. \textbf{(v) Execution conformance:} observations and commands must follow the model (A1--A4, Section~\ref{sec:runtime-boundary}).

\paragraph{Why matching and reconnection both matter.}
Cell's prefix $\rho_B,m_B,\mathsf{start},\mathsf{stop},\rho_A$ finishes every command with inspection pending: physical matching alone would admit the clear target $z_B$, whose $m_A$ violates that duty, so monitor matching excludes the reset. Conversely, disabling controllable loop $b$ in a one-state endpoint with loops $a,b$ and goal $\mathit{true}$ preserves legality, deadlock freedom and safety~\cite[Defs.~3.9--3.10, 4.3]{Nahabedian2020} but loses $b$-continuations; FG-DUCS requires a supplied controller's continuations, which safety alone does not, without excluding richer DUCS encodings.

\section{What a Returned Policy Establishes}
\label{sec:interpretation-execution}
\label{sec:proof}
A returned policy is a certificate for the supplied game: from every old entry and under every modeled outcome it keeps every active monitor safe, reaches a quiescent handover after finitely many events without fairness, and restores the selected endpoint's continuation (Theorem~\ref{thm:correctness}; Proposition~\ref{prop:endpoint-continuation}). Whether it also establishes the modeler's requirement or the platform's execution depends on two further premises: the monitor and its initial state must express the intended duty, and observations and commands must follow the model. \Needspace{18\baselineskip}
\subsection{Synthesizing and Checking a Policy}
\label{sec:algorithm}
The solver applies established strong-planning and on-the-fly reachability principles~\cite{Cimatti1998StrongPlanning,TripakisAltisen1999,CiolekDCS,CassezEtAl2005TimedGames}:
\begin{enumerate}
\item Discover all entries. Mark discovered goals winning with rank zero and matching endpoints.
\item Expand a safe non-goal: query all UC successors or, if quiescent, all outcomes of the next enabled control. Discover each successor; unsafe states stay losing.
\item Repeatedly promote a safe UC-enabled state when every UC successor wins, or a safe quiescent state when some enabled control has only winning successors. Retain these choices and set its rank above every retained successor rank.
\item Return a policy once all entries win. Otherwise expand remaining discovered states and retry unresolved quiescent states with their next controls. If neither remains possible, return the nonwinning region.
\end{enumerate}
TA~\ref{ta:lazy_algorithm} gives the complete pseudocode (Algorithm~\ref{alg:otf}), including cache and queue bookkeeping. Exploration may reach the whole game.

\Needspace{9\baselineskip}
\input{technical_fragments/synthesis_statement.tex}
\begin{proof}[Proof idea]
Promotion preserves complete successor sets of strictly smaller rank, giving safety and finite completion. Finite exhaustive retry ensures termination. At failure, every UC-enabled nonwinner has a nonwinning outcome, and every enabled control at a quiescent nonwinner has one. This region prevents completion (full proof: TA~\ref{ta:source_synthesis}).
\end{proof}
Ranked policies are checked for entry coverage, enabled choices, all-outcome closure, decreasing ranks, safety and matching goals, and losing-region checks verify the counter-outcomes above; both are relative to the generated successors and endpoint predicates~\cite{HofmannEtAl2016MuCertificates} (TA~\ref{ta:certificate_checks}).

\subsection{Giving Requirements Their Intended Lifetimes}
\label{sec:monitor-meaning}
The game interprets a requirement through its monitor and the state installed at activation. Two intended lifetimes occur in the inputs: a duty that depends on the history before the start, and an invariant that begins when its requirement starts.

\paragraph{Other declared lifetimes.}
An interval monitor begins at update entry. A requirement retaining duties from prior histories needs \emph{residual inclusion}: every continuation accepted by its initialized monitor must be allowed after every history in the declared scope. That scope must contain the actual histories, since an empty scope makes inclusion vacuous. For the inherited GSM message-processing input with interval guards, an analytical policy starts the new rule $\Box\neg decode.2$, then permits $decode.3$ and output before handover. It rejects $decode.2$ and covers every entry within twelve events (TA~\ref{ta:activation_scope}). This illustrates start-scoped enforcement; it is not a saved solver output.

\subsection{Executing the Policy}
\label{sec:runtime-boundary}

Execution requires four premises (TA~\ref{ta:execution_proof}):
\par\noindent\textbf{A1: Observations.} Endpoint observations preserve component/monitor states and same-labeled edges.
\par\noindent\textbf{A2: Event progress.} Control disables every unselected controllable, retains every UC event and outcome, and eventually observes a next event and successor.
\par\noindent\textbf{A3: Commands.} Commands start quiescently and finish atomically, finitely and without failure, reporting a modeled successor.
\par\noindent\textbf{A4: Boundaries.} Entry copies the old state; quiescent handover installs the selected compatible state. Both are finite, failure-free and linearizable~\cite{HerlihyWing1990}.

Under A1--A4, execution reaches handover within the entry rank (Theorem~\ref{thm:realization}). A2 adds no fairness preference or time bound. History-based duties also require the declared scope to contain actual activation histories. Internal divergence and unobservable outcomes violate these premises.

\section{How Granularity Changes Feasibility}
\label{sec:granularity-analysis}
Granularity is part of the supplied contract: a batch removes the states between its member operations, which may be indispensable or harmful. We first identify obstructions to a specified merge, then give local conditions under which a merged policy can be implemented by separate commands.

\subsection{The Compared Contracts}\label{sec:granularity-contracts}
Partition transfers, old stops and new starts separately into blocks. A transfer block $B\subseteq I$ permits every target in $\prod_{i\in B}g_i(s_i)$ in one step. A stop block removes all its monitors before observation; a start block initializes all its monitors afterward, at the unchanged component tuple. Each monitor active throughout a block applies every member-label transition once. These transitions must commute pairwise on every monitor state, making their order irrelevant. Mapped precedence must remain irreflexive and acyclic. Ordinary behavior, entries, endpoints, relations, initializers and targets stay fixed; quiescence and all member guards apply.

\subsection{Obstructions and Capacity}
\input{technical_fragments/granularity_obstruction.tex}
Readiness gates motivate the constructed Rolling contract~\cite{e6_kubernetes_deployments,e6_mongodb_enterprise_replica_set}. It abstracts capacity during paused maintenance, rather than modeling those platforms' continuous-service policies. It starts with $n$ ready replicas, no spares, and an interval floor of $m$ ready replicas. A transfer boots its replicas; each becomes ready after one UC event, with no waiting loop. Service self-loops are controllable. The all-new, ready target restores capacity; service may pause during the update.

\begin{proposition}[Rolling threshold]\label{prop:rolling-threshold}
For $n\ge2$, $1\le m<n$ and $1\le k\le n$, fixed consecutive batches of size $k$ (with a smaller final remainder) admit safe finite completion iff $k\le n-m$.
\end{proposition}
\begin{proof}
Some mandatory batch has size $k$. Its transfer leaves at most $n-k$ ready replicas, so $k>n-m$ violates the interval. Otherwise, transfer one batch only when all replicas are ready, disable service, and retain every UC readiness outcome before the next transfer. Readiness never falls below $n-k\ge m$. With $u$ old and $b$ booting replicas, $2u+b$ strictly decreases on every selected transfer and every UC event, reaching zero exactly at the target. Thus all maximal runs finish without fairness.
\end{proof}

\subsection{When a Batch Can Be Serialized}\label{sec:serialization}
Finer commands need not preserve a merged winner. Consider two one-state components sharing UC labels $x,y$. Component 1 permits only $y$ before transfer and only $x$ afterward; component 2 has the opposite loops. Neither label synchronizes in the all-old or all-new product, but either mixed product has a UC loop. Separate identity transfers therefore lose, whereas joint transfer reaches the target at rank one. A controllable loop keeps both endpoints deadlock-free. TA~\ref{ta:granularity-reverse}--\ref{ta:serial-transfer} give the complete contract and a second counterexample in which the intervening UC event terminates but destroys target compatibility.

For component $i$, let $A_i^v$ be its UC alphabet, $E_i^v(s)$ its enabled UC labels and $B_i^v(s)=A_i^v\setminus E_i^v(s)$ its blocked UC labels. A blocked participant prevents synchronization; an absent label does not. Require
\[
 E_i^{\mathrm{new}}(s')\subseteq E_i^{\mathrm{old}}(s),\qquad
 B_i^{\mathrm{old}}(s)\subseteq B_i^{\mathrm{new}}(s')
 \quad\text{for every }(s,s')\in g_i.
\]
The transfer must offer no new UC label and remove no blocker; the table lists the allowed changes per label, where ``absent'' means outside the local alphabet, hence not participating in synchronization.
\[
\begin{array}{l|ccc}
\text{Old status}\;\backslash\;\text{New status}&\text{Absent}&\text{Enabled}&\text{Blocked}\\\hline
\text{Absent}&\text{yes}&\text{no}&\text{yes}\\
\text{Enabled}&\text{yes}&\text{yes}&\text{yes}\\
\text{Blocked}&\text{no}&\text{no}&\text{yes}
\end{array}
\]
Removing a blocked label can thus enable a global event even though it enables no local transition. With equal alphabets, the criterion reduces to enabledness inclusion.
\begin{proposition}[Context-independent quiescence]\label{prop:local-uc-main}
For a fixed local transfer pair, the two inclusions above hold iff that replacement preserves UC quiescence in every finite synchronous context whose other states stay fixed.
\end{proposition}
\begin{proof}[Proof outline]
The inclusions prevent a new globally enabled label. Conversely, a context can expose either a newly enabled label or a removed blocker, while blocking all other UC labels. TA, Proposition~\ref{prop:contextual-uc}, gives both constructions.
\end{proof}

\Needspace{5\baselineskip}
This equivalence concerns quiescence alone. Whole-policy serialization also needs the Cartesian outcomes, commuting monitor effects and valid precedence of Section~\ref{sec:granularity-contracts}.
\begin{proposition}[Serial transfer preservation]\label{prop:serial-transfer}
For transfer-only merging under the comparison rules of Section~\ref{sec:granularity-contracts}, if every transfer satisfies the local UC criterion above, a merged winner implies a fine winner. A finite-memory serial expansion preserves the merged policy's selected endpoint continuations.
\end{proposition}
\begin{proof}
Fix an order for each batch and disable ordinary controls during its expansion.
\emph{Quiescence and enablement.} Each transfer preserves quiescence with the other components fixed, including earlier replacements. Thus every partial batch is quiescent. Unexecuted transfers retain their source coordinates and nonempty images; irreflexive mapped precedence forbids dependencies within a block.

\emph{Monitor safety.} Every partial outcome extends to a Cartesian batch outcome. Commutation yields the same final monitor states. An intermediate absorbing error would persist to the safe batch endpoint, a contradiction.

\emph{Completion and reconnection.} Replacing ranked coarse steps by these finite sequences preserves completion and the selected endpoint. Each completed run gains exactly $|I|-b$ events, for $b$ transfer blocks. The expansion uses finite memory; memoryless sufficiency gives a fine winner but need not preserve the merged endpoint selection (TA~\ref{ta:serial-transfer}).
\end{proof}
The main solver does not automate this expansion; Section~\ref{sec:rq2} checks a separate implementation on one restricted family. Threads, a constructed worker model with a bounded queue, passes the local test: its identity transfers between identical old/new graphs leave enabled and blocked sets unchanged. Rolling fails: its new booting state enables a UC readiness label absent in the old ready state. This is the table's absent-to-enabled case, yet Rolling wins under its capacity threshold. Failure of the test leaves feasibility open (TA~\ref{ta:constructed_contracts}).

\Needspace{10\baselineskip}
\begin{proposition}[Serial transfer and boundary preservation]\label{prop:serial-all}
Let $\mathcal B$ partition all commands under Section~\ref{sec:granularity-contracts}'s comparison rules. Suppose every transfer in a nonsingleton block satisfies the UC criterion; each start-block monitor self-loops on other member starts at every common admissible initialization tuple; and each safe stop-block member state stays safe on other member stops. Every merged winner then has a finite-memory fine expansion preserving its selected endpoint continuations. Each expanded run gains exactly $|\SigmaU|-|\mathcal B|$ events.
\end{proposition}
\begin{proof}[Proof outline]
Boundaries leave components and quiescence unchanged. The conditions protect monitors newly started or awaiting removal; commutation and error absorption handle monitors active throughout. The checkpoint proof above applies to every block (full proof: TA~\ref{ta:serial-boundary}).
\end{proof}
Boundary conditions protect members started or removed together: after splitting, one can observe another's command. TA~\ref{ta:serial-boundary} gives counterexamples without this protection.

\section{Implementation and Evaluation}
\label{sec:evaluation}
\subsection{Design and Implementation}

RQ1 examines granularity mechanisms on constructed contracts; RQ2 checks the implementation and selected requirement interpretations; RQ3 compares exploration costs within the same solver on \ApplicationContracts{} adapted contracts. WIN and LOSS denote proved winning and losing games; timeout (TO) and incomplete (Inc.) denote unresolved results.

Each inherited input has three supplied configurations: Base adds no interval requirement; R1 protects selected gap actions; R2 requires selected boundaries before transfers. TA~\ref{ta:benchmark_inputs} gives events and sizes. A production-cell case separately tests availability. The archived fork's generalized-reactivity DUCS backend (Legacy) solves a different subsequent-control problem and supplies separate reference results.

\paragraph{Implementation.}
Our Modal Transition System Analyser (MTSA) extension~\cite{paper:MTSA2008} checks certificates~\cite{McConnellEtAl2011Certifying}; Link checks connected controllers, entries and targets. An independent oracle parses restricted Finite State Processes (FSP)~\cite{MageeKramer2006}. Explicit finite inputs save losing membership; FSP benchmarks report statistics.

\paragraph{Generative tool use.}
Generative artificial intelligence (AI) assisted contract and example design, proofs, the Java solver and frontend, Python checkers, experiment drivers and execution, analysis and editing. Validation used certificates, exhaustive algorithm checks, source and automaton comparisons for initialization, saved-output table checks and primary sources for citations (TA~\ref{ta:implementation_details}).

\paragraph{Constructing the benchmark inputs.}
Nine inputs adapt eight DUCS sources; PC1 and PC2 share a parent. They have 1--5 components, 4--131 old entries and 3--26 update commands (TA, Table~\ref{tab:input-structure}). Adaptations make production-cell tool results UC while the inherited arrival cycle stays state-gated, so withholding controllable work and output lets pending results, resets and arrivals finish without a total arrival budget; they shorten Railcab transfers while retaining both outcomes, remove PowerPlant's duplicate initial-environment transfer declaration, and change safety and ordering. Their necessity for completion and equivalence to the source problems are unestablished (TA~\ref{ta:additional_populations}).

MTSA synthesizes fixed endpoints from FSP and prepares monitors and initialization tables before search. Interval requirements use a constant post-entry state; physical observers survive commands and transfers. The Cell$_n$ family extends Cell to $n$ stations with holder-dependent initialization. S3--S4 detail these paths and their preparation costs.

\paragraph{Exploration variants.}
All variants share the game and checks. Lazy queries outcomes for one controllable event at a time; Eager queries outcomes for all controllables. Direct-Full first constructs the reachable graph; Full+UC additionally prunes controls at UC states. Update-first prioritizes update commands~\cite{HiranoEtAl2024ODUCS}. Query/retry orders affect exploration, not execution (TA~\ref{ta:exploration_order}).

\paragraph{Design and measures.}
RQ3 uses one Windows/Xeon host, a 64~GiB heap and a 1,200~s Java Virtual Machine (JVM) cap: $27\times4$ game cells plus 27 Legacy references. Medians require five completed runs, unresolved trials remain capped, solver time includes checks, JVM time includes preparation, endpoints, startup and output, and Legacy uses its native timer. Mac pilots are excluded (TA~\ref{ta:implementation_details}, \ref{ta:memory_policies}; S4).

\subsubsection{A Source-Derived Calibration Case}\label{sec:pc2-case}
PC2-Rolling supplies two arm models and transfer maps, 12 old and 13 new requirements, an interval keeping one arm operational, and fixed controllers. From these, FG-DUCS generates 25 requirement boundaries and two transfers, without a prescribed order. Requests are controllable and completions UC; transfers enter calibration and preserve initializer observers. Erasing calibration recovers the operational process, not whole-problem equivalence (TA~\ref{ta:pc2-generation}).

The policy calibrates each arm in turn, covering all \PCTwoCaseEntries{} entries with at least \PCTwoCaseMinOperationalArms{} arm outside calibration. Every outcome decreases rank from at most \PCTwoCaseMaxRank{}; Link checks reconnection. Thirteen source invariants hold from their starts through the remaining start-only suffixes. This checks reached tuples up to handover; Section~\ref{sec:monitor-meaning} gives GSM's analytical example with ordinary actions after activation.

\paragraph{Why the fixed merge loses.}
Apply Lemma~\ref{lem:mandatory-obstruction} with $B$ containing only the joint transfer and $R$ the safe states reachable before it. Old plants lack calibration actions; all other steps preserve both readiness bits. Thus $R$ is closed before $B$, whose every outcome calibrates both arms and violates the interval. The merged solver and fine Direct-Full nevertheless time out at \VThreeESixPCTwoCap{}~s/\VThreeESixPCTwoHeap{}~GiB. Restricted-transfer controls retain both-LOSS and incomplete cases (TA~\ref{ta:additional_populations}; S1--S4).

\paragraph{Inherited inputs: no observed change.}
The \VThreeEOneTrials{} comparisons are nine inherited inputs $\times$ two configurations (Base/R1) $\times$ three merges (transfers, boundaries, both). None changes its decision; merging reduces or preserves the state count. R2 names individual update events and is excluded. Their total physical transfer relations and absent post-transfer startup/calibration phases exclude those particular separation mechanisms (S4.1). The null result remains empirical: total transfers do not imply safe merging, because requirements may reject the joint successor, as PC2-Rolling shows. The local criterion covers 12/18 Base/R1 transfer-only pairs in six models: 11 WIN/WIN and one LOSS/LOSS (TA, Table~\ref{tab:serial-inputs}). PC1/PC2 remove blocked UC labels and Railcab enables one; their other six pairs are empirically WIN/WIN without this guarantee. No inherited policy was converted.

\paragraph{Expanding saved batch policies.}
An offline transformation expands all ten saved Threads backpressure policies ($n=2$--6, queue capacity 1 or 2). Checks cover 620 entry occurrences, every UC action and selected outcome, decreasing ranks and the same endpoint; every case passes with exactly $n-1$ added events per completed path. This restricted family has identical OLD/NEW behavior, idle identity transfers, no requirement monitors and no UC interleaving in added phases. It validates neither a general converter nor speedup (all cases: TA~\ref{ta:saved-serial-expansion}).

\section{Related Work}
\label{sec:related}
\label{sec:expressiveness}
\paragraph{Update environments and synthesis.}
Global state-preservation transitions generate update environments~\cite[Sec.~V]{Yamauchi2020Partitioning}; DUCS permits a partial global transfer relation $R$, without UC quiescence~\cite[Sec.~4.2, Defs.~3.7, 5.1]{Nahabedian2020}. Directed controller synthesis (DCS) uses lazy products, UC priority and backward propagation for eventual goals on every trace~\cite[Sec.~IV]{CiolekDCS}; nonblocking on-the-fly DCS requires a marked extension of each finite trace~\cite[Def.~4]{CiolekEtAl2023OTFDCS}.

\paragraph{Requirements and configuration changes.}
Temporal adaptation, scenario updatability and Live Synthesis handle changing obligations~\cite{ZhangCheng2006ALTL,Ghezzi2012DynamicScenarioUpdate,PanzicaLaManna2013CorrectnessDynamicUpdates,FinkbeinerEtAl2022LiveSynthesis}. FG-DUCS uses scoped requirements and residual reasoning~\cite{Dwyer1999Patterns,RosuHavelund2005Rewriting}. Dynamic feature configuration supports individual and joint changes, feature-dependent requirements and retained/reset state; its joint feature swap avoids invalid intermediate configurations~\cite[Secs.~4--7]{ThuijsmanReniers2024DynamicFeature}.

\paragraph{Switching and operational updates.}
State attraction ensures bounded reachability of a startup set from every request state within a task language~\cite[Def.~2, Alg.~1, Thm.~1]{NooruldeenSchmidt2015}. Switched supervisory control provides safe, deadlock-free switching and reinitialization between supplied safe/live supervisors; its full problem requires every finite trace to extend to a switching opportunity~\cite[Problem~1, Sec.~3.3]{MeiraGoesLafortune2020Switching}. FG-DUCS generates the mixed system from local transfers and requirement lifetimes, with explicit grouping.

\paragraph{Granularity and atomicity.}
Lipton preserves final states through atomic reduction under commutation and nonblocking~\cite[Sec.~3]{Lipton1975Reduction}. Partial-order methods omit redundant interleavings~\cite[Secs.~4--5]{Godefroid1991PartialOrders}. Our expansion preserves winning strategies and selected endpoints through intermediate quiescence, transfer outcomes and monitor observations. Network-update synthesis distinguishes switch/rule granularities, preserving linear temporal logic (LTL) properties while reaching prescribed final packet traces~\cite[Secs.~3.1--3.2, 4.3]{McClurgEtAl2015NetworkUpdates}. FG-DUCS handles requirement activation states and environment-chosen transfer outcomes, completing from every entry without fairness; a general translation is unestablished.

\Needspace{3\baselineskip}
\section{Threats to Validity}
\label{sec:threats}
\noindent\textbf{Internal validity.}
Certificates, exhaustive checks and independent restricted-FSP parsing mitigate correlated faults from shared authorship, AI and code. Direct-Full is in-house; external solvers and randomized orders are untested. Five-run medians exclude extended trials. Null results, losses, timeouts, memory failures, interruptions and faster or smaller alternatives are retained (S4). Memory sampling can miss peaks and cannot isolate heap use or bottlenecks.

\noindent\textbf{External validity.}
One host and related models limit generalization; repeats are not independent applications. Inherited inputs lack explicit precedence; only Railcab transfers branch. Constructed cases assume finite startup, reporting, recovery and election; selection may favor separations. Deployment prevalence, model-adaptation effects and platform conformance remain unestablished. Activation analysis covers only the stated saved cases; failure repair is excluded. The supplementary exploration bound depends on the default query order (TA~\ref{ta:exploration_order}).

\section{Conclusion}
\label{sec:conclusion}
FG-DUCS generates an update game between verified controllers from local transfers, requirement lifetimes and initial obligations. Winners finish safely from every entry under all outcomes without fairness, restoring selected endpoint continuations. Serialization conditions, obstructions and a capacity threshold delimit granularity. Constructed separations coexist with \VThreeEOneTrials{} unchanged inherited comparisons; synthesis decides \LazyDecisions{}/\ApplicationContracts{} adapted contracts. Commands require global UC quiescence; execution conformance, continuous service and elapsed-time bounds remain unestablished.
