# Generated-artifact checking bound and limitations

Author-side proof/code inspection completed September8, retained verbatim in AUTHOR_PROOF_CHECK_RAW.json. Parent checked the argument against the actual larger-chunk-first comparison. The initial PROOF_DRAFT and all earlier manifests/results remain unchanged. This is an author mathematical argument, not mechanical certification or independent blind review.

For c>0,p>0 and old suffix f, all slopes after a are strictly below c, including zero-tail positions. Delta therefore strictly increases there. The recorded crossing t satisfies Delta(t-1)<p<=Delta(t), and s_t<z=s_t+p-Delta(t-1)<=c. Exact prefix/plateau/singleton/suffix equality and support max(length(f),t) establish Rf on all nonnegative integers. Premium zero preserves f. Starting from the terminal zero root proves all suffix values and the earliest protection policy under the inherited cap theorem.

## Why generated sharing bounds comparison work

Let h be the maximum tree height and K the nodes freshly allocated by one prepend. A contiguous range decomposes into O(h) subtree and run chunks, including at most two partially clipped runs. Complete pivot-run atoms along boundary paths also count; the initial draft's wording suggesting only two run chunks was too narrow.

Aligned shared subtrees wholly inside an unchanged range are never expanded by equal_ranges. Suppose the first such expansion were of S. Its counterpart has not been expanded. The other front is either S itself, which the algorithm skips, or an ancestor T starting at the same position. Positive run counts imply length(T)>length(S), so the implementation expands T first. Both contradict expansion of S. The argument is independent of numerical multiplicity.

Contract maximal common subtrees wholly inside the range into atoms. On the new side, uncontracted nodes are fresh or boundary nodes, so their number is O(K+h). Both sides have the same canonical decreasing run sequence; after removing common atoms, the old side has the same number of exposed runs. Binary branching bounds common atoms by this exposed structure. Since the comparison never expands the common atoms, it performs O(K+h) expansions/skips/run comparisons. The prepend uses a constant number of logarithmic AVL splits/joins/searches, with standard height-sensitive split/join telescoping, hence K,h=O(log(n+1)). A constant number of range comparisons and queries per job gives O(n log(n+1)) checking arithmetic on these generated artifacts, plus O(m) structural verification for m serialized nodes. Construction allocates and serializes O(n log(n+1)) node records. Input validation additionally charges |E| and supplied-order sorting. Dictionary/set access uses the implementation's usual amortized/expected constant-access assumption; integer arithmetic charges operand bit lengths. These are not unconditional wall-time bounds.

## A valid certificate outside that bound

Take k zero-premium jobs followed by a forced chain with (c,p)=(i,i),i=1..k. The positive suffix has slopes k,k-1,...,1 of count one. Materialize two disjoint node-ID copies A and B of that profile and alternate A/B for the zero-premium roots. All semantic identities remain valid, and total artifact size can remain O(k log k), but each alternate-root comparison scans Theta(k) runs, producing Theta(k²) work. The constructor never emits this pattern: p=0 returns the identical root. Thus arbitrary supplied artifacts, even valid ones with plausible counters, have only the output-sensitive guarantee. Metadata cannot certify that an arbitrary supplied artifact was generated by this implementation.
