# Retained logical snapshots and exact compression work: exploratory02

This new source-informed attempt preserves all Valkey01 results and their input-byte resource definition. The purpose is to remove an avoidable full reprepare/read on every retry, and to measure a source-level kernel-operation count rather than silently equating8/16/24 input bytes with distinct SHA1 compression costs. It is an author application feasibility study, not final performance evaluation, upstream adoption, or a production demand claim.

One initial HMGET captures all component versions/blobs; the client computes their transforms outside Valkey. Every subsequent validation runs as one atomic EVALSHA. If it rejects, it returns current versions and the current blobs for precisely the dirty components. The client rehashes only those blobs, retaining clean digests; this creates a logically fresh full snapshot at the preceding validation's atomic capture point. New writes between that capture and the next validation form the next independent footprint word. No additional snapshot read is needed. If it accepts, it hashes dirty components inside and atomically publishes the full current digest/version vector. First-call direct full-server publication remains an admissible same-operation baseline. Completion after a rejected branch may choose direct in the abstract comparison, but is dominated by accepting the preceding dirty observation when residual accept cost<=direct cost.

For fixed component SHA1 compression weights w_i and P=sum_iw_i, record L as the actual number of source SHA1Transform calls within payload transforms on the server, W as these plus outside client payload transforms, and Qwire=1+Qvalidation for the prepared protocol. Direct has Qwire1, L=W=P. Script loading/setup, writer commands, diagnostic readbacks and all wire bytes are distinct counters. Payload bytes, version scans, publication, policy decisions, copying/GC and elapsed time are not erased from reporting, but L/W are kernel compression counts, not total instructions or a whole-blocking-time bound.
