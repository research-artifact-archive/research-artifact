# Transfer domains and the joint-calibration obstruction

The hypothesis that the two transfer domains never hold simultaneously is false for this fixed PC2 input. Each source relation contains all seven old local states. An independent Python parser expands the frozen OLD process at K=1 and synchronizes it with the supplied old endpoint controller: 81 reachable controller/physical states, 216 edges and 36 distinct physical tuples. Both domains hold in **81/81** states. Sixteen of those states have no physically enabled UC event. These are counts for the raw controller/plant product, not the 126 augmented initial embeddings reported by the update adapter.

The strengthened checker explicitly parses the controller alphabet extension for `stamp` and `stampOk`. Its 28 labels equal the old plant alphabet, so a missing controller edge really disables that event rather than permitting controller stutter. All 144 physically enabled UC edges over the reachable product remain controller-enabled with the same synchronized successor. This checks composition with the supplied controller; it does not independently re-synthesize the GR controller. The checker imports neither E1 Post nor another update solver.

Evidence: `validation/independent_support/check_old_domains_v2.py` and `old_domain_product_v2.json`. The original v1 check and the first v2 parser failure are retained: the exported alphabet suffix uses the MTSA printer's `+{{stamp, stampOk}[1..2].` syntax, and the initial stronger parser expected a different closing brace. Only the new validation parser was corrected; the source input, controller export and experiment stayed unchanged.

A concrete old-controller trace is `Q0 --in[1]--> Q1 --in[2]--> Q79`. Both arms are then in ARM, both transfer domains hold and no UC event is physically enabled. The joint transfer maps the arms to CAL_ARM/CAL_ARM. Each transfer observation clears the corresponding CalReady bit, so the always-active interval requirement `CalReady1 || CalReady2` becomes false. The same simultaneous calibration effect holds for all 49 possible raw old-state pairs because every target of both relations is a CAL state. `validation/joint_calibration_obstruction.json` records the parsed mappings and this trace.

This is a post-transfer safety obstruction, not an empty-domain obstruction. Before the merged transfer both physical components are OLD, so neither can execute a calibration-completion event. Normal old actions and stop/start events leave the readiness bits unchanged. Completing an all-new update requires consuming the mandatory transfer, but its joint observation enters the absorbing interval error. The earlier and extended measured timeout cells nevertheless remain TO unless a completed native synthesis result is returned.

For the additional observer coordinates, read-only inspection of fixed E1 `MtsaRevisedOtfDucsAdapter.compileComponents` (lines 1433–1494 in the frozen source lineage) shows that every augmented old source with a raw transfer target contributes that target, with the same observer vector, to the new seeds and then to the transfer relation. Thus observer augmentation does not introduce an extra transfer-domain restriction for these total raw relations. This is a source-code argument, not an independently measured count of the 126 augmented embeddings.

The existing v2 output reports zero transitive precedence edges. The 16 raw product states passing the physical UC guard therefore also have the source-domain and precedence conditions required for the initially pending transfers. No equality between this raw count and the number of eligible augmented initial embeddings is asserted. Eligibility alone does not establish that the successor is safe.
