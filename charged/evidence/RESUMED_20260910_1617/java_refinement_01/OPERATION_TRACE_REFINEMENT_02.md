# Java completed-operation trace refinement with explicit observations and pending writes

Author proof draft addressing review156 C4. It refines the listed whole-kernel wrapper interface, not arbitrary Java clients, the whole Java memory model, or a mechanically verified JDK binary. The theorem equations and all previous experimental outcomes are unchanged. The previous author check is ../AUTHOR_JAVA_REFINEMENT_GODEL.md. No native execution is introduced by this document.

## Source boundary and admitted executions

Use the pinned OpenJDK17 ConcurrentHashMap source in RESUMED_20260907_1942/source_text/openjdk17_runtime/ConcurrentHashMap.java. There is one foreground controller. Each job has a distinct permanent existing key; keys can share internal bins. Key hash/equality/comparison methods are stable, side-effect-free and terminate normally. Values are nonnull; equality for validation is reference identity. Every published Value is deeply immutable after construction, including arrays; its job tag and shape are preserved by kernels and external writers. An external own-key write normally completes, installs a reference not previously used for that job, and neither removes a key nor changes completed milestones. At every finite execution prefix the admitted environment can perform another such write. Resource exhaustion, arbitrary exceptions, recursive map updates from a remapping function, key deletion, and unfair nontermination of a selected API operation are outside this contract.

The kernel reads only its immutable own snapshot and immutable completed-parent outputs. Its payload computation is pure and performs its specified fixed work. A newly allocated output is treated as a fresh opaque reference carrying that payload: reference renaming preserves aliasing, validation and specified observations. This allows allocation without claiming that repeated allocations have equal Java references. The controller does not observe numeric allocation counters, event-log order, wall time, scheduling probes or mutable live-parent reads inside the kernel. A kernel that uses any such value to choose its result or controller action requires another model.

For the normal baseline, excluding live_parent and other deliberate mutants, the retained observations are reference equality, payload, saved wrapper return, done-parent outputs, selector state and Q/W/L. The excluded observations are numeric IDs, event order, diagnostic failure witnesses, clocks and scheduling probes. The particular instrumented BudgetBlindCallbacks.java has diagnostic ids.incrementAndGet, event writes, Thread.yield and resource counters. Its selector reads dependencies, the mode family and call allowance; the arithmetic payload kernel reads snapshot data and done-parent seeds, not diagnostic ids. Erasing these diagnostic fields/actions and consistently renaming remaining object references specifies the wrapper experiment's payload/action projection. This is not an observational equivalence for callers inspecting all fields, writer histories, log order or numeric IDs. The finite event checker validates those instrumentation traces separately. The abstract theorem is stated for the pure wrapper contract, not inferred by declaring every instrumented instruction pure.

## Concrete state and abstraction relation

Let H be the concrete heap, including map nodes, immutable Value objects, the foreground's done array, snapshot/record store and locals. Add proof-only variables: a finite ordered queue Delta of committed external writes deferred during normalization, whose elements are committed write labels (key, new reference), not writer callbacks to be rerun. Let eta be an injective map from live/retained Value references to opaque abstract identities, extended to new references without identifying distinct objects. It carries the immutable payload needed by the fixed kernel and preserves reference equality.

The abstract state is (x,M,R,ell). M(i)=eta(done[i]) once the job completes and is thereafter immutable. R contains only snapshot/record handles actually available for selection by the foreground. A separate ghost history may record past computations, but never makes a discarded handle selectable. The simple native loop keeps only its current before/prepared handles; it does not implement the entire retained/copying strategy class. A general wrapper implements that class only when it really stores the corresponding handles. Available computed records have the form (i,eta(s),P_i,eta(z)); P_i is the tuple of M(p) for completed immediate predecessors. Records may be copied/reselected but cannot be fabricated or retagged. ell contains the controller state and selected handles. A completed source result is put in M from the API's saved return/prepared value, never by rereading the live map.

At normalized wrapper boundaries the live-reference relation is

    decode_eta(H.map)=apply(Delta,x),
    b_concrete=b_abstract+|Delta|.

Here apply replays each queued committed assignment label in its concrete order. b_concrete is a ghost count of committed map publications, not the diagnostic Run.writes counter: that counter increments inside the writer callback before CHM performs its store, and can temporarily lead the commit count. At synchronized completed-writer boundaries their counts agree. When Delta is empty this is ordinary equality of live abstract and concrete values. The queue is needed because a writer may run after a remapping result is fixed but before the public API returns. For example, a cached call publishes z, a later writer publishes y, and compute still returns z. Mapping the return-time live map directly to the pre-suffix abstract x would be wrong.

decode_eta follows MOVED/forwarding nodes to the appropriate table and reads stored Value references, ignoring node allocation identities. Its definition is used at stable operation boundaries; this document does not claim a one-line heap function adequately describes every intermediate resize state. The source's forwarding/monitor invariants connect these boundaries.

## Wrapper transition and observation table

Write r=(i,s,P_i,z) for a selected preparation and v for the value observed at P3. Every successful completion additionally sets M(i) to its saved output. The table gives increments at completed wrapper boundaries in units of one specified kernel iteration work w_i.

| Wrapper operation | Returned controller observation | Abstract update | Delta(Q,W,L) |
|---|---|---|---|
| Prepare from a captured snapshot | new record handle r | add r to R; no completion | (0,w_i,0) |
| Cheap match | success flag | x_i:=z; M(i):=z | (1,0,0) |
| Cheap mismatch | failure flag only | clear selection; retain R,M and x | (1,0,0) |
| Fresh completion | completed output z' from current v and P_i | x_i:=z'; M(i):=z' | (1,w_i,w_i) |
| Cached match | completed output z, optionally match flag | x_i:=z; M(i):=z | (1,0,0) |
| Cached mismatch | completed output z', optionally mismatch flag | x_i:=z'; M(i):=z' | (1,w_i,w_i) |

The conditional-replace wrapper returns its boolean. A validation-only compute wrapper discards the raw returned value and exposes only its match flag. On mismatch that raw value is v, whereas replace returns false; the unwrapped APIs therefore are not observation equivalent. An interface exposing v must add it to the abstract result/history and prove its own correspondence. The validation-only wrapper code discards that additional value. In this particular fixture its valid input relation g=0,r=v always selects the replace branch at native103, so the validation-only branch104 is not executed by these cases. Its correspondence is a source/API argument, not empirical branch coverage from this fixture. Returning v from a mismatch callback may store the same reference again; its abstract live state remains unchanged and it is not a fresh external write.

The per-operation claims follow directly from the branch and protected-store paths above. Matching records contain the exact own snapshot identity and completed-parent tuple. Nonmatching cached/fresh calls compute from v while same-key writes are excluded. All output payload computations use those immutable operands. A source allocation extends eta with a fresh reference and cannot change an existing record's identity.

## Grouping internal work and structural steps

For BudgetBlindCallbacks the array-length invariant is |src.a|+number_of_parents(i)=8w_i. Initialization establishes it; the writer allocates an array of the same length and preserves slot; every kernel does the same. Each parent iteration and array iteration increments work once, so a whole kernel adds8w_i. A protected kernel additionally increments protectedCalls[i] once. Thus at completed source wrapper boundaries:

    Q=sum_i(callbacks[i]+conditionals[i]),
    W=work/8,
    L=sum_i w_i*protectedCalls[i].

The general wrapper uses w_i directly; the factor8 belongs only to this fixture's implementation scale. We group a completed kernel segment and its full work into one labelled abstract operation and compare costs at the corresponding completed-operation boundaries. No completed result reference or full-cost abstract Prepare is assigned to an earlier unfinished source prefix. An instruction-by-instruction forward simulation would require pending computation descriptors and reserved-token/cost invariants and is not claimed here. Internal work++ steps are therefore not being asserted to be zero-cost stutters. Monitor waits, internal traversal, guard instructions, allocation and elapsed time are outside Q,W,L; no total-time identity follows.

Pure structure changes preserve stored Value references: list transfer2505–2509, tree transfer2523–2524, treeification2675–2677 and untreeification2697 copy those references into replacement nodes. Such structure-only actions preserve x,M,R and counted kernel work. A concurrent value-changing writer during transfer remains a write transition; it is not hidden as structural stuttering.

## Normalization to gates

Fix a completed source execution and the specified foreground observations. Label each completed kernel segment by its captured immutable operands, its actual returned output reference and its full work. Contract that segment into one abstract Prepare, retaining the capture event before it. The state immediately after abstract Prepare corresponds to a source boundary after the actual kernel has returned; the output reference therefore exists and eta can include it. Writes committed between capture and that return go into Delta, preserving their order and count, and are flushed before the next selected foreground operation's abstract effect. This is a completed-trace transformation, not a statewise assertion that the output existed at capture. Any intervening foreground inspection is itself that next operation, so it observes the same updated live value. Local record operations receive the same handles and alias relations.

Similarly, after P4 the return value and success flag are fixed in locals. Writes from P5 through P6 can be deferred into Delta; the milestone uses the saved result, so its value is preserved. The concrete map may already contain their results, which is exactly why decode_eta(H.map)=apply(Delta,x), rather than decode_eta(H.map)=x, is maintained. The next gate flushes Delta before the next operation effect. Same-key writer order is preserved. Kernels do not read other mutable entries, so these writes cannot change a contracted pure body. This argument preserves the declared foreground observations and resource totals, not arbitrary writer observations or diagnostic event interleavings.

If execution ends with a nonempty Delta, an observational extension by a zero-foreground-cost terminal write suffix replays it and preserves the final live map. For a completion-cost objective, one may instead stop at the completed foreground prefix, but then must not claim final live-map identity. This draft includes the suffix explicitly.

The fixture's n<=5 fixed-key run does not exercise treeification or resize. Those structural paths are covered by the stated source/API reasoning, not added to its native coverage count. Diagnostic erasure and fresh-reference renaming describe a possible trace projection under the allowed scheduler, not equal execution under an identical fixed machine schedule.

Because normalization never adds a write, a concrete source execution with at most B writes maps to an abstract execution within B and with identical completed-wrapper Q,W,L. For the explicit upper-bound strategies, control executes only a bounded number of finite preparation/call segments and completes because each selected source operation terminates. The matching abstract trace transfers their resource bounds. This does not infer termination of arbitrary low-level code from completed traces alone. It is not a claim that all low-level API calls or all arbitrary Java programs belong to this interface.

## Concrete realizability of the lower-bound adversaries

After the foreground has fixed a target job/mode and its finite pre-gate store, suspend it before entering that API. Run a successful writer compute on the target key, installing a legal fresh reference of the required shape, then resume the foreground. No foreground monitor is held at this point, even if bins collide. The new reference differs from every target snapshot captured in the preceding finite store. Hence cheap comparison fails and cached mismatch recomputes inside; a fresh call already protects its full kernel. Lower-bound realizability does not require inserting a write inside an acquired monitor or identifying its last physical acquisition.

Repeat this construction using the target adversary's finite unconditional bound. For Theorem1, before the next target write, actual writes v<=f+p, where f is noncompleting target calls and p is completed targets. While f<=r and p<k, v+1<=f+p+1<=r+k<=B. The adversary stops after f=r+1 or p=k. A source policy that avoids completion through infinitely many free actions against this same bounded adversary is inadmissible; no unjustified arbitrary truncation argument is needed. For Theorem2 the additional write belongs to a distinct finite environment witnessing universal-cap admissibility, not to the original lower-bound execution's evaluation budget.

This proves the source operation realization needed for the stated frontiers, assuming the fixed API/source synchronization properties and normal selected-operation progress. Full JDK/JMM verification, instrumentation-preserving equivalence and broader client observations remain outside this result. The prior draft and its source-aware author critique are preserved. The two definition gaps identified there are resolved here by using completed-operation trace grouping and separating available handles from ghost computation history. This remains an author proof requiring an external manuscript-level assessment; it is not a mechanical certificate.
