# Reproduce and verify

Start with [the main reproduction instructions](../README.md#reproduce-the-study), then the [detailed guide](../docs/REPRODUCTION.md).

`check.py` runs saved-evidence validation in a fresh restored workspace. `materialize.py` verifies and restores files using `layout.json`. `check_extensions.py` checks E-series/ext1–7 data and small independent finite games. `scripts/` preserves earlier helpers plus the portable finite runner. `solver-variants/` gives measured source identities and baseline-relative patches. `campaign/` and `validation-protocol/` preserve original experimental programs/configurations; dated protocol status text may describe pre-run plans. `previous-validation/` is explicitly historical validation from the preceding artifact version, not the result of this update.

`check_paper_displays.py` checks the current paper's diagrams, table populations and plotted values against the distributed evidence. It runs as part of `check.py`, or independently with `python3 -B reproduce/check_paper_displays.py` from the repository root. Its fifteen checks include Cell and Policy requirement bands, Base/R1/R2 completed-pair strata, Policy's seven-state certificate path, the PC2 phase table, all 126 saved PC2 full-prefix history rows, the selected all-entry active-suffix graph analysis, a separate all-thirteen source/graph analysis, and all-contract definition/adapter preparation times and activation-closure counts from the original archived metrics. The checks read distributed inputs, certificates and archived timing summaries. They require neither Java nor TeX and leave the display inputs unchanged.

`build_paper.py --output work/paper` builds the main paper, technical appendix and supplement in a fresh copy. It requires `latexmk` and XeLaTeX on `PATH`; see the [paper instructions](../paper/README.md) for the complete command and document roles.

New runs must use fresh output directories. A saved-evidence PASS is not a new Java measurement or an external proof. Full benchmark reruns require the recorded resources and variants.

`check_pc2_histories.py` replays the saved plant/observer edges and independently cross-checks safe-prefix reachability in the existing graphs. It checks the displayed 39/21/66 partition against `results/pc2-activation-histories.json`; `--output` can write a new full report. It runs no Java, synthesis, input generator or timing trial. The analysis covers one reached activation tuple; negative full-prefix histories are not active-lifetime safety failures.

The placement check follows this archive's main/appendix source inclusions. The main paper contains the Cell scenario and completing paths in Figure 1, the supplied-input/output comparison in Table 1, the lazy synthesis algorithm, and the complete 14-pair absolute-cost plot in Figure 2. Technical Appendix A contains the detailed synthesis and contract-to-game proofs and promotion cases; B contains the complete Cell contract and residual derivation; C contains the complete Policy contract. H gives the detailed interface table, and O contains the constructed families, all 108 same-game outcomes and separate capped, Full+UC, controlled and Travel evidence. The saved Cell and Policy diagrams retain their states, actions and ranks. The main text states the numbered synthesis and adequacy results, requirement-lifetime primitives and opposing Policy boundary orders. These checks verify placement and preservation, not mathematical validity.

`check_pc2_active_suffix.py` checks domain closure, decreasing ranks, absence of non-goal deadlocks, domination of completion by the selected start, the five-edge suffix and recorded endpoint match. It reproduces `results/pc2-active-suffix.json` without running a solver. It does not validate the compiler, endpoint semantics independently, other requirements or runtime conformance. The [claim map](../docs/CLAIMS.md) also identifies mathematical arguments that are supplied as proofs rather than executable empirical checks.

`check_pc2_all_act_saved.py` independently recomputes and compares every field in `results/pc2-all-active-obligations.json`. Its separate `check_pc2_all_act.py` reader parses the thirteen source invariants and reconstructs their 24 ordinary observer coordinates, replays 870 saved edges, binds all 126 entries to old hot-swap predecessors, checks strict-rank completion and the mandatory thirteen-start chain, evaluates each active invariant, and checks linked endpoint alignment. It keeps the original selected-requirement checker and report. Run `python3 -B reproduce/test_pc2_all_act.py` for 38 adverse/positive fixtures on copied saved inputs. These checks do not verify the full initializer, compiler, endpoint semantics independently, or runtime behavior.

The display check also protects the main-paper placement of `activation_duty_main.tex` and `history_scope_main.tex` and snapshots both files. The earlier initializer source remains in the archive; all saved-data readers and result files are unchanged.

`results/supplement-checks/source_invariant_lookup/analyze_new_invariants.py` independently parses the original 46 NEW invariant positions and checks their 138 saved monitor occurrences and 900 non-error lookup cells. Reproduce the finite semantic analysis with `python3 -B results/supplement-checks/source_invariant_lookup/analyze_new_invariants.py --artifact-root . --output /tmp/fgducs-source-invariants.json --csv /tmp/fgducs-source-invariants.csv` using new output filenames. The recorded 35,283 pair/label checks establish source-invariant fidelity for these finite objects under the stated observer rules; physical state decoding, actual activation keys, fallback initialization, runtime behavior and general compiler correctness remain outside scope. This analysis runs no Java, synthesis or performance trial.
