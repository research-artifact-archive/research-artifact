# Rolling readiness witness, v1

This is a finite model inspired by Kubernetes Deployment readiness and unavailable-replica budgets. It is not a Kubernetes implementation or incident reproduction. The direct anchor is [Deployments](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/); PodDisruptionBudgets do not govern Deployment rolling updates.

Each of the n replicas is initially OLD/ready. Transfer changes it to NEW/booting. A one-shot uncontrollable `ready_i` event changes booting to ready. Normal `serve_i` events are controllable self-loops at ready. Thus the fixed all-old and all-new endpoints are safe, nonblocking single-state closed loops, but booting replicas cannot serve. The endpoint controller permits all service actions. The single interval monitor tracks the number ready and rejects counts below m. Initialization is q_n at the all-old endpoint.

The finite one-step startup abstraction has no waiting loop and uses no fairness assumption. Once a booting replica exists, E1's existing uncontrollable priority forces readiness before further controlled updates. This abstracts finite preparation and makes no claim that real readiness failures are absent.

Group size k means consecutive groups of at most k replicas; a final group may be smaller when k does not divide n. The hypothesis is WIN iff k ≤ n−m: at least one group has size k, and no group larger than the availability slack can transfer safely; legal groups can be updated and become ready before the next group. Generated coarse contracts retain n physical components and invoke the documented same-package input-adapter bridge to E1's existing grouped-contract construction flag. No solver, Post, goal, or JAR is changed.

`gen_rolling.py` creates inputs and config exactly once. `v1/` fixes n=2..6, m=1..n−1, k=1..n: 70 Lazy cells, then 15 Direct-Full k=1 cells, then 15 E1 transfers comparisons. The last 15 compare complete reachable Post games against the generated k=n contract before synthesis. Each final cell has one 32 GiB / 1,200-second whole-JVM trial, with the global 2026-09-30 09:39 JST start cutoff. Preflight cells are separately labelled, never substituted for final measurements.

`validate_endpoints.py` independently reconstructs the full plant × controller × endpoint-requirement product from JSON, checks initial projections, transition equality, safety, nonblocking, and reference/type constraints. `analyze_rolling.py v1` checks observed threshold results, E1/generated merged equivalence, Lazy/Direct-Full decisions and state counts, all WIN certificate ranks and physical availability, and stored LOSS region counts. It produces `tables/threshold.csv`, `validation/rolling_results.json`, and the observed ME path `validation/me_path.json`.

All construction and expectation choices were registered with the coordinating chat before final execution. The initial public-builder shared-label assumption was corrected from source inspection before any solver trial. An unused public product-component draft is retained under `common/design_archive`; the final model uses the registered existing-E1 builder hook and preserves component/state order.
