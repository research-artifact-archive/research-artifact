\subsection{Why the Generated State Represents the Contract}
\label{sec:contract-adequacy}
A \emph{local update history} $\ell=z(a_1,o_1)\cdots(a_n,o_n)$ records the old entry, events and realized local successors. Components follow their active-version transitions and transfers; monitors fold their declared active intervals. Commands obey precedence, guards and UC quiescence. A source policy selects controllable labels, retains every UC and permitted outcome, and safely completes every maximal history at a matching quiescent target. Technical Appendix~\ref{ta:source_synthesis} defines these contract operations on histories.

\begin{proposition}[Adequacy of the generated update game]
\label{prop:contract-adequacy}
For an eligible contract, map each local update history to its current component tuple, active monitor memories and unexecuted commands. Histories with the same image admit the same next events and all the same local outcomes, agree on safety, and have the same handover targets. This map gives a label- and outcome-preserving correspondence between local update histories and paths of the generated game. A history-dependent policy satisfying the source obligations exists exactly when a winning policy exists in that game.
\end{proposition}
\begin{proof}
Fold a source history into its current tuple $F(h)$. At entry this is $\Init(z)$. Each ordinary step uses the same participating component edges and full Cartesian product of outcomes; each transfer uses the same quiescence/order tests and $g_i$, advances active monitors and consumes its command. Stop removes its own monitor before observation; start installs its initializer after observation by existing monitors. Thus every label and outcome has exactly the same successor image, and safety and matching targets agree.

Induction maps source histories to game paths. Conversely, choose an old tuple witnessing the entry and lift each edge by this one-step correspondence, also for infinite paths. A game policy lifts through $F$; applying a source policy to consistently lifted game histories gives a history-dependent game policy. Both directions preserve UC events, all selected-label outcomes, unsafe prefixes, deadlocks and infinite avoiding runs. Theorem~\ref{thm:correctness} supplies a state-based winner or excludes every history-dependent winner, completing the equivalence.
\end{proof}
This proves correspondence for the supplied contract; requirement meaning and Java frontend correctness remain separate obligations.
