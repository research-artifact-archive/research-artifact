# Exploratory native policy comparison, fixed before first run

This is a new author-controlled experiment, not a final evaluation, production workload, or independent review. It keeps every previous Deephaven failure and result. The policy API is an opt-in author modification of the pinned upstream program. It does not fix the off-domain maximum-row-key traversal defect.

The 84 primary cells are the Cartesian product of lambda in {1,3,10}, seven schedules in their Java source order, and {compiled, upstream, threshold, protected}. Each cell constructs a fresh 31-row immutable binary-tree structure, three refreshing expansion directives, and a 16-row viewport. Source ID, parent, and row sets never change. Only Sentinel data and the (unchanged) Action column are written, with exact modified-column sets. This supersedes the previous exploratory driver that rewrote key columns and used ALL column notifications; its observations remain preserved.

Schedules: no update; one full K cycle; one full V cycle; one split V cycle; one split K cycle; two split V cycles; one full K plus one split V cycle. Each action occurs at the next matching unprotected body BEGIN. A full action starts and completes a real ControlledUpdateGraph cycle. A split action starts a cycle at one BEGIN and completes it at the next. Before any policy acquires the graph lock, an already open cycle is completed. Protection may prevent later scheduled actions from being triggered, so q is an upper bound, not a claim of identical executed writes across policies. All policies face the same action-responsive environment program. Empty/unreached suffixes are reported through executed cycles and event traces, not excluded. The controller sees no future schedule actions.

The compiled policy is the exact two-mode chain DP for K before V, with B=2q. At (j,b), choose the cheaper of (1+lambda)w_j+F(j+1,b) and w_j+max(F(j+1,b),F(j,b-1)); at b=0 the fast expression is w_j+F(j+1,0). Ties choose fast. The remaining budget decreases only on an observed inconsistent CHECK. Fixed source-derived caps are w_K=M+1=4 and w_V=(M+1)(3H+5)+(N+1)+4R=176, H=5. The protected cost cap is (1+lambda)w. These are caps on selected logical counters; model equality with actual native work is not presumed. Source prerequisites and the 2q argument are in author reports04 and06 and remain subject to root verification before paper adoption.

Upstream retains its two-concurrent-attempt limit and five-second duration fallback. Threshold uses no B: try fast until cumulative failed attempt cap reaches lambda*w, then protect (inherited ski-rental-style comparator). Protected always locks. The three opt-in logical-cost policies disable the elapsed-time fallback because wall-clock delay is not priced in this objective; this behavioral difference is disclosed. All policies retain original locking, validation, exceptional and nested-snapshot semantics. Such exceptional paths are outside the resource theorem domain and must be reported, not silently treated as budgeted failures. Instrumentation is inactive without a target observer.

Record every body BEGIN/END, selected logical operation, native CHECK, writer cycle phase, policy decision, and returned row. Cost is measured selected work plus lambda times the selected work performed while the graph lock is held. Also compute the conservative charged cap for the observed sequence. Neither metric is elapsed time, total instructions, allocation, waiting, scheduler work, or end-to-end application cost. Setup/compilation/Gradle time is retained separately in the run receipt and log. No CPU speedup or saved developer effort is inferred.

All 84 cells must remain in the denominator. Primary terminal classes are SUCCESS, FAILURE, TIMEOUT, INVALID, and NOT_RUN for missing observations after a build/harness failure. The execution wrapper has a 180-second process-group bound; each native cell has a 30-second loop bound and 15-second writer request bound. Malformed/corrupt input, wrong output, quota excess, body-cap excess, invalid compiled decisions, missing cells, and a mismatch between abstract ledger and native traces are falsifiers. Revisions after a failure require a new directory and reason, preserving original source bytes, log, XML and raw. No unchanged result rerun or exclusion is permitted.

After the first run, a separate Python checker will reconstruct DFS output, actual update epochs, body counters, clock consistency, decisions and costs from raw events. That checker is author verification, not a blinded assessment. Any later stress matrix, stronger invariant, or additional baseline is a separately recorded exploratory successor.
