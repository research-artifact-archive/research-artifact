# Reader initialization and operation-count boundaries

This is a post-matrix source clarification. SOURCE_REFINEMENT01.md, all three original executions, raw source and adverse controls remain unchanged. No new native execution occurred.

The conditional traversal proof requires initialized traversed components, valid reference/RCU lifetimes, and no concurrent initialization outside the participating writer discipline. It is incorrect to state without this qualification that every parent/name/length/content assignment takes rename_lock. In fixed v6.12, allocation initializes those fields outside that lock. d_mark_tmpfile also changes inline name bytes and length under d_lock without advancing rename_lock or d_seq. Its normal paths mark before inode instantiation, filesystem notification and fd publication. That observed order supports ordinary initialization use, but is not an exhaustive publication proof for every filesystem/module.

An unhashed child is already in its parent's child list, and overlay backing-file paths may hold an extra reference before marking. Neither 'unhashed means invisible' nor 'exactly one reference until initialization' is a valid proof. A reader given an initializing child could combine an old length with new name bytes while the global sequence remains unchanged. The necessary native publication-to-reader path has not been established, so this conditional interleaving is not reported as an actual Linux bug or counterexample to an admitted execution.

The read-only source inspection identifies ordinary rename/exchange/alias migration paths through d_move/d_exchange/d_splice_alias and their rename_lock participation. It also identifies the initialization exceptions above. A syntactic C/H assignment search is not alias analysis or a machine-checked whole-kernel writer proof. The KUnit fixtures are fully initialized before reader/writer startup and are within this stated scope.

The fixed source proof remains an upper refinement for source events, rather than a native multi-job minimax equivalence. The public dentry_path_raw invocation count is one under every policy. The manuscript's Q counts logical validation/completion blocks. On the384 retained cached/two-cheap pairs, re-counting the six named RCU, sequence and guard primitive boundaries gives maxima10/10, whereas logical Q gives2/3. For the138 one-write pairs the primitive totals are10/8 and guard counts1/0; for144 two-write pairs both primitive totals are10 and both guard counts1. The remaining102 no-write pairs have primitive totals4/4 and guards0/0. All body vectors and outcomes are unchanged.

These counts are reconstructed from the fixed source and branch ledger, not measured machine calls or internal spin iterations. Q_SENSITIVITY04_PLAN.md defines the units; every pair and input/source hash is retained in Q_SENSITIVITY04_ROWS.json and its receipt. The logical distinction is therefore dependent on the declared operation boundary. It does not establish an upstream caller SLA or a separation under all native counting conventions.
