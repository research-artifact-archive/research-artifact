Some requirements intentionally refer to events before activation. In that case, the modeler declares the admitted histories, and the initialized monitor must preserve every remaining obligation of those histories. A more restrictive monitor may reject feasible updates; an empty set of admitted histories makes this check vacuous.

Our saved checks distinguish safe histories consistent with the current observation, references beginning at update entry, and whole histories that may include earlier violations. Technical Appendix~\ref{ta:residual_formal} defines the residual-language inclusion precisely; S3 states the conditions for each interpretation. These interpretations answer different questions and must be chosen to match the intended requirement.
