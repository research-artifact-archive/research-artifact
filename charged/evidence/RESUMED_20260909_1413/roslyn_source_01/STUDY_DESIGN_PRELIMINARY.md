# Scoped Roslyn source integration design, before a patched build

This is a development plan, not a sealed final evaluation or an observed application benefit. The baseline source is NuGet 5.0.0's repository revision 6c4a46a31302167b425d5e0a31ea83c9a9aa1d09. Preserve its archives and failed builds. First obtain an unmodified baseline build. The 14:13 session is authorized until 18:00 JST; start closeout at 17:50.

The concrete path is Workspace.OnDocumentTextChanged(DocumentId, SourceText, PreservationMode) -> OnAnyDocumentTextChanged -> SetCurrentSolutionAsync. The source transformation computes a new immutable Solution and synchronizes linked document contents, clears private scratch on every invocation, then validates the old Solution identity under _serializationLock before publishing and notifying exactly once. Its generic documentation requires pure transformations, but that alone does not authorize moving all workspace transformations under the semaphore. We restrict the new path to ordinary SourceText text replacement. Loader, project, configuration and other generic updates retain the old path.

A research-only internal context applies to one explicit foreground thread and one batch of document updates. It contains only a mode and a global cheap-failure allowance r as selector inputs. The unchanged optimistic mode, a two-mode fallback, and cached completion share the same patched binary and instrumentation. Writer budget B and document/loop sizes remain in the driver. Other threads bypass the research context and execute the original update path. The context may count calls, preparations, protected transformations and mismatches and emit trace hooks. Hooks are observation/scheduling instrumentation; they do not become selector inputs. No stable public API or upstream-ready patch is claimed.

The two-mode policy, after r failed identity validations, acquires the source semaphore, reads current Solution and transforms once there. The three-mode policy instead freshly prepares outside, acquires the semaphore, reuses on identity match or transforms the latest Solution once there. In both, preserve the original early no-op return, a no-op return after protected recomputation, WithNewWorkspaceFrom, onBeforeUpdate, publication, onAfterUpdate and disposal ordering. Only a cheap failure spends the global allowance. The original mode continues preparing/retrying outside. EnsureEventListeners remains before lock acquisition, as required by source issue64681. A pre-acquisition hook is available to all modes, including fresh protected mode, to avoid giving one mode privileged scheduled writes.

Proposed evaluation construction: an actual C# workspace with 1,8,64,256 projects linked to one target source file and an unrelated background document. A foreground batch changes the linked target four times; the background thread changes only its unrelated document. Its writes change Solution identity and can invalidate a prepared target update even though they preserve the target content. Fix r in0,1,2 and B in the deduplicated set {0,r,r+1,r+4}. Force one complete external update at each of the first B foreground pre-lock opportunities. Thus B=r compares equal foreground call counts, B>r executes genuine cached mismatches, and the unbounded optimistic source is a third control. Record actual writes even if they differ across policies; no workload equality is inferred from quota alone. The proposed counts and repetitions are not final until all input constructors, harness, source patch and exact binaries are materialized and hashed. No timing sample has been run.

Normal-return validation must include final target/background contents, all linked documents, captured Solution outputs, callback/event counts and order, and source operation counters. Separate development/regression cases cover identical SourceText no-op, equal text with a new identity, required-document absence, and a document removed between preparation and validation. Exceptions and no-ops do not inherit fixed-positive mandatory-work equalities. Standard SourceText instances and the tested host services are required; arbitrary extension callbacks, loaders or SourceText subclasses may reenter or block and are outside any protected-transformation guarantee.

This integration can support a bounded-call and protected-transformation upper guarantee for its source path. Its Solution transformations allocate persistent data and defer compiler work; their observed duration is neither a fixed mandatory w nor WCET. Shared Solution identity also differs from separate own-key jobs. Therefore do not transfer the full game's minimax theorem, claim reduced parsing work, or infer prevalence/whole-editor speedup. Any promotion requires an explicit source-to-contract argument and all adverse cases retained.
