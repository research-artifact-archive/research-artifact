# Source-derived missing-document error reentry study 01

Before execution. The existing source calls virtual Workspace.GetDocumentName while constructing a missing-document ArgumentException. Instrumented original computes that path outside the serialization semaphore, while patch03 can move it inside two/three protected recomputation. Test a Workspace whose name hook performs one unrelated normal text update. This is a deliberately reentrant host counterexample probe, not an ordinary-workload sample. It is outside the old nonreentrant prototype scope but directly tests the source-derived virtual-call obligation.

Fixed cases: modes original/two/three, r=0/1, missing before entry or removed at the first pre-lock opportunity; 12 patched cases. Unmodified library has two missing-before cases, r labels0/1 (no contention-hook claim). Removal uses a separate writer joined before lock. The name hook must finish its unrelated update and the outer request must throw ArgumentException. Observe all process outputs and snapshots. Each case runs once in its own process; watchdog3seconds, then terminate. Native TIMEOUT/FAILURE/INVALID stays adverse, even when predicted; no favourable relabelling. New fixes use successor patch/run namespaces. No prior measurements or source results are rewritten.

Expected hypothesis before outcomes: patch03 two/r0 missing-before and two/r0/r1 removed-between, plus three/r0 removed-between, may block recursively acquiring the same semaphore; original and other cases may return the source exception. The test cannot prove arbitrary extension safety or reproduce an upstream host bug, and is not a counterexample to the pure terminating-kernel paper theorem.
