# Workflow repair and observed arrival budgets

Two additional standard stages preserve the preceding31 stages. Run from the repository root into a new output directory:

```
python3 -B charged/reproduce.py workflow-repair --out work/workflow
python3 -B charged/reproduce.py arrival-budget --out work/arrival-budget
```

`workflow-repair` recomputes 8,960 authored unpriced DAG conditions (61,246 known-budget roots and6,208 quantified common-policy searches),37,248 positive-toll conditions (216,282 known-budget roots), and37,368 threshold-certificate checks. The last group reuses the37,248 observed inputs and adds120 mathematical profile cases; it is not an independent empirical population. A separate checker reconstructs123 exported certificates and all equations, and two executable policies enumerate8 and10 terminal paths. The constructor and checker share the model specification; implementation separation is not a blind review. Each of the three groups also has four detected corruption controls. Arithmetic outputs are compared with the saved originals. Timings and process memory may differ by machine.

The [unpriced proof](evidence/RESUMED_20260910_0343/partial_repair_dag_01/PROOF.md) establishes a common budget-unaware optimum for the persistent fresh-reset DAG model exactly when retries are unavailable or every job's maximum repair work is reachable with one write. The [positive-toll analysis](evidence/RESUMED_20260910_0343/partial_repair_toll_dag_01/PROOF.md) gives a sufficient bound for every DAG, an exact bound for independent jobs, and a necessary sink bound. The [threshold certificate](evidence/RESUMED_20260910_0343/partial_repair_toll_dag_01/THRESHOLD_CERTIFICATE_PROOF.md) represents the budget-unaware history policy by a downward-closed cost allowance; this is an application of finite game recursion, not a new general minimax principle. A three-job chain has a common optimum that first-accept does not realize. Adding precedence changes the admissible known-budget comparator; it does not imply that adding a dependency reduces cost.

The [history-count correction](evidence/RESUMED_20260910_0343/partial_repair_toll_dag_01/HISTORY_COUNT_CORRECTION.md) explicitly replaces an erroneous intermediate claim that the comparator saturation threshold bounds every observation's minimum write count. The implementation clips only the cost-target budget index, never accumulated cost. Original notes and the initial pre-input macOS resource-limit failure remain available. The threshold representation used803,712 states on the observed grid, versus616,039 in the Boolean existence search; no state-count or runtime advantage is claimed. These finite checks corroborate the proofs, with no native software equivalence or measured operational benefit inferred from them.

`arrival-budget` reanalyzes7,392 unchanged native timeline records, including6,160 measurement and1,232 warm-up records from four saved campaigns. It reconstructs each policy's actual foreground-period publication count and validates the source-level call/inside-write bounds. Five corruption controls are detected. This is post-outcome descriptive analysis: the foreground-period count depends on the policy's end time and is not a shared causal intervention. The measured batch spans exclude lock acquisition and release and are not wait-time or SLA bounds. See the [fixed analysis plan](evidence/RESUMED_20260910_0343/arrival_budget_analysis_01/PLAN.md) and [all results](evidence/RESUMED_20260910_0343/arrival_budget_analysis_01/run01/SUMMARY.json).

Both stages are arithmetic replay or reanalysis of saved measurements. Neither invokes native Roslyn, collects new timing samples, establishes general deployment importance, or changes any earlier adverse result. All source and public-byte hashes and explicit author-path projections are recorded in `PROVENANCE.json`; private author-helper conversations and third-party source PDFs are not distributed.
