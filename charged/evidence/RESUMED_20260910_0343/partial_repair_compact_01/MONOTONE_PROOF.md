# Monotone-profile denominator buckets

This supplements PROOF.md; it changes only the exact threshold-feasibility implementation. Assume every H(k) is present and H=G is nondecreasing, with H(0)=0. Singleton footprints and positive component weights satisfy this condition. The compiler validates it once and otherwise retains compact01's linear search. All other assumptions, optimal-ratio isolation, comparator, conventions and limitations remain as in PROOF.md.

At a fixed least-consistent expenditure e and original call cap q, the candidates with comparator index j form the integer interval [max(0,qj-e), min(m,q(j+1)-1-e)]. Its denominator b=mu+G(j) is constant. For a threshold R=p/d>=1 and integer scaled costs, unacceptability is exactly d*(mu+H(k))>p*b, equivalently H(k)>floor(p*b/d)-mu. This equivalence also covers b=0: positive/zero is unacceptable and zero/zero=1 is acceptable. Monotonicity means a bucket contains an unacceptable k iff its last H exceeds this cutoff. If its first exceeds it, the first is minimal; otherwise an exact upper-bound binary search returns the minimal unacceptable k. Buckets are visited in increasing k, so the selected k is exactly compact01's smallest unacceptable cost. Both implementations therefore return identical paths and feasibility, preserving all of the previous greedy-dominance and exact-isolation proof.

There are at most floor(m/q)+2 nonempty buckets in one step. Buckets without a violation need constant work; there is at most one binary search per step, in a bucket of length at most min(q,m+1). Across at most q steps, one feasibility decision costs O(m+q*(1+log(min(q,m+1)))) arithmetic comparisons/operations. Profile validation costs O(m) once per compilation. The same bisection requires O(1+log U) decisions. For singleton footprints, including sorting, the total is O(m log m + (m+q*(1+log(min(q,m+1))))*(1+log U)) arithmetic operations and O(m+q) space. This is a bound on arithmetic operations; exact scaled-cost and e bit lengths, sorting/input generation and output encoding still count. O(log U) bits suffice for isolated fraction arithmetic, and e/bucket indices require O(log(qm)) bits. U is mu+W after integer scaling, so the bound is not strongly polynomial in numeric encodings.

The separate version2 checker validates H=G and monotonicity, then checks each purported upper-path step and the maximum numerator at the last candidate of every earlier bucket. It uses direct rational cross multiplication through the original policy predicate, no compiler bisect or integer cutoff. Terminal all-acceptable verification uses the same bucket-max principle. At most q prefix scans cost O(m+q) operations after O(m) validation. The lower certificate is the original q-step explicit history and is checked independently as before. Regression and scale artifact analysis additionally use the unchanged linear checker; this extra outside-timing audit is not included in measured construction cost.

This result is a model-specific optimization of the already established finite-horizon minimax method. It neither establishes literature-wide novelty nor changes the uncalibrated common-cost assumption, general-footprint profiling cost or native semantic limitations.
