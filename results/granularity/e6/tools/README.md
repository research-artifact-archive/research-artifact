# E6 family harness

Use `python3 -B tools/run_family.py FAMILY freeze`, then `preflight`, then `run`; `analyze` runs no JVM and `audit` rechecks frozen files. Paths to the family can be absolute or relative to the invoking directory. The scripts locate E6 and the existing E1 JAR from their own paths. Main runs and preflight trials take the same shared advisory lock; a busy lock fails before creating a second JVM or a run directory.

`config.json` schema is `e6-family-run-v1`, with `family`, `version`, `heap:"32g"`, `timeout_seconds:1200`, `trials:1`, `start_cutoff`, `deadline`, and ordered `jobs`. Every job has `id`, family-relative `input`, `merge`, `solver`, and optional `parameters`, `expected_decision`, `compare_input`, `compare_merge`. Comparison options invoke WitnessDriver's exhaustive Post check before synthesis. `preflight_jobs` is a list of job IDs; `preflight_job_options` maps IDs to comparison-only overrides, so a check can be restricted to preflight. `endpoint_checks` and `analysis_commands` contain argument arrays executed from E6. `frozen_paths` contains E6-relative files in addition to automatically captured config, inputs, common Java/classes and tool scripts. All shared implementation edits must finish before the first family freeze.

Freeze and all raw records are create-only. Each trial records invocation, raw stdout/stderr, adapter result and certificate, and completion with artifact digests. A timeout remains TO even if a late result file exists. Missing states, queries, rank, and certificate sizes are never imputed. No retry is implemented. A failed analysis is retained and does not silently remove or reorder trials. The deadline is the only planned schedule truncation; all unstarted jobs remain explicit rows. Python aggregation always starts in a fresh subprocess after each terminal cell, avoiding a cached analyzer definition.

`summary.csv` and `tables/results.csv` contain every schedule row; `status`/`decision` distinguish completed checked WIN/LOSS from TO, ERROR, INVALID, RUNNING and not-started states. `expected_check` compares completed measurements to preregistered hypotheses; mismatches are retained. Measurements use adapter field names: states, oracle queries, distinct nonempty queried buckets, materialized successor transitions, returned WIN rank bound or discovered LOSS certificate size, and separate preparation/synthesis/checking times. Mac times are reference measurements, not Xeon comparisons. `loss_summary` preserves the adapter's limited local certificate evidence. `tables/results.tex` is a longtable requiring `booktabs` and `longtable`; family-specific compact tables can be generated by the family analysis command.

`raw/runner_finished.json` is written only after the final frozen-file check and before a fresh final aggregation. This marker indicates the serial schedule has terminated, not that all scheduled cells were measured. `NOT_RUN_DEADLINE` remains explicit in the final tables.
