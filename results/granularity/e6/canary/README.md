# Canary evidence family

`v1/` is the frozen 15-parameter-pair, 60-trial series. `design/v0_literal_unimplemented/` records why the first literal hidden-outcome predicate was not representable by the fixed action-only tester. `design/v1_reports/` records the accepted observation-based model before measurement. Both are retained.

The model has n logical replicas (n=2..6), at least m required healthy replicas (1<=m<n), two adversarial transfer outcomes, finite uncontrollable health reports, and controllable restoration. Restoration is an abstract recovery action; it is not a claim about how the real CrowdStrike incident was repaired. The interval tester observes reports. An independent postprocessor separately checks actual physical health on every returned WIN certificate state, including unreported outcomes. LOSS evidence is checked for an all-broken transfer result and an uncontrollable report path to the absorbing monitor error.

Sources of input: `gen_canary.py` is deterministic and reads no measurements; `validate_canary.py` independently reconstructs endpoint plant/controller products and checks local transitions, transfer outcomes, monitor behavior and grouping. The fixed E1 JAR is used read-only through the common adapter. A shared transfer label in the generated all-at-once input is explicitly declared through the existing E1 grouped-contract constructor, without changing its Post or goal semantics. `analyze_canary.py` reads preserved results and certificates only.

Run with the common harness from E6: `python3 -B tools/run_family.py canary/v1 preflight` and then `run`. Freeze already exists and must not be overwritten. The first three n=2,m=1 cases are separate preflight records. Main jobs are ordered by n, then m, with fine Lazy, E1-merged Lazy, explicitly grouped Lazy and fine Direct-Full. Every E1-merged job also compares its complete reachable Post game against the explicit all-at-once input. Each main job is a single trial; preflight results are not substituted for its measurement. A common JVM lock serializes families. No new trial starts at or after 2026-09-30 09:39 JST.

Results: `v1/summary.csv` and `v1/tables/results.csv` retain all 60 scheduled cells; `pairs.csv` has all 15 parameter pairs; `canary_summary.json` reports completed comparisons and unresolved cells. `certificate_checks.json` retains the physical-health minimum for each checked WIN and an explicit within-certificate report path for each checked LOSS. `mechanism_reasons.csv` gives one evidence sentence per checked certificate. `table_canary.tex` is the compact state/rank/certificate table; `results.tex` is the complete longtable. Missing states/queries/ranks are never zero-filled. All times are Mac reference measurements.

The practice anchor is staged rollout with feedback, described in CrowdStrike's official [preliminary review](https://www.crowdstrike.com/en-us/blog/falcon-content-update-preliminary-post-incident-report/) and [technical root-cause analysis, page 6](https://www.crowdstrike.com/wp-content/uploads/2024/08/Channel-File-291-Incident-Root-Cause-Analysis-08.06.2024.pdf). Perfect one-shot reports, the availability threshold, independent adversarial outcomes and guaranteed restoration are explicit modeling choices, not empirical conclusions from those documents.
