# Native atomic-call calibration — exploratory pre-outcome plan

Route SCIENTIFIC. This answers the open external merit deficit about declared call prices. It measures actual ConcurrentHashMap operation paths in OpenJDK17 with OpenJDK JMH1.37. It does not infer a worst-case timing guarantee from average timings, production workload prevalence, or human impact. The paper's exact theorem remains about declared fixed resource prices.

Use a standalone Maven/JMH build with annotation processing, returned values to keep work observable, isolated JVM forks and fixed warmup/measurement windows. APIs match the current native harness: identity-based immutable values, permanently present keys, no resizing/removals, get+whole-array preparation, conditional replace, validation-only compute and fresh compute with the same whole-array kernel. The measurement experiment contains no external writer; match and mismatch paths are explicitly constructed separately. Its purpose is fee/operation estimation, not interference evaluation. Allocation and ordinary GC are included. State construction is excluded and recorded as setup.

Fix payload lengths1,8,64,512 and two map layouts (one target bin without collision; eight distinct keys sharing its bin). For each of8 states measure7 paths: get, prepare(get+kernel), replaceMatch, replaceMismatch, validateCallbackMatch, validateCallbackMismatch, freshCallback. This gives56 path/state cells, each with2 fresh JVM forks,3 warmup iterations of200ms and5 measurement iterations of200ms (10 retained measurements per cell). All parameters and Java/build/JVM/JMH bytes must be fixed before any timings. Allow at most1200s for the campaign and90s per fork; preserve all failures/timeouts/invalid/unexecuted cells and every raw JMH record. No outcome-dependent rerun or input removal. Instrumentation-free microbenchmark outputs do not replace the separately checked native semantic traces.

Calibration analysis is fixed before data: let observed means be t_prepare, t_replace_match/mismatch, t_callback_match/mismatch, and t_fresh. Report direct residual p_raw=t_fresh-max(callback means)-t_prepare, including negative values. Also fit w,v,k,p>=0 by nonnegative least squares to six paths (get is a separate diagnostic): predicted prepare=w; both replace paths=v; both validation callback paths=k; fresh=w+k+p. Record every residual and the largest relative absolute error. A cell is representable by this approximate average-cost model only when w>0 and maximum relative error<=20%; this exploratory tolerance is not a statistical guarantee or source proof. Do not silently clamp a negative p_raw and call it measured protection premium. Report the fit and its limitation.

For every representable fitted state, analyze a fixed price-sensitivity family rather than select a winner: all ordered pairs of the four measured payload lengths within the same layout, budgets0..8, protected-resource multipliers lambda in{0,0.25,1,4}. The elapsed-only lambda0 point uses fitted p; positive lambda points add an explicitly declared protected-work premium lambda*w and are not elapsed-time predictions. Each pair's own calibrated v/k/w/p is retained. Compare the exact three-mode DP with the exact two-mode restriction; keep all equality/negative-fit/no-benefit results. A strict value improvement is evidence only for that measured-price/declared-weight region, not observed end-to-end speedup.

Primary methodology sources: https://raw.githubusercontent.com/openjdk/jmh/1.37/README.md ; official samples JMHSample_08_DeadCode.java and JMHSample_12_Forking.java. OpenJDK website fetch403 is retained as an acquisition limitation; official GitHub1.37 source supplies the harness instructions.
